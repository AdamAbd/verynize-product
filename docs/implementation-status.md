# Implementation acceptance status

Updated 2026-10-30. This records actual implementation and tests, not a claim that every Wonder feature is equivalent. The original vendor checklist remains in wonder-roadmap.md.

## Implemented and exercised

- Shell/library: Wonder-reference dark chrome, floating tools, docked chat, local Inter typography and Lucide-based icons, responsive 1440/1000px layouts, persistent local files/folders, grid/list/search, rename/duplicate/archive/restore and publication-aware Public/Private filters. File switches detach previous native-save and cloud-room state; native opens and shared-room joins have separate library records. Delayed native Save completion is canceled after a document switch; responses from superseded cloud operations are discarded.
- Settings: local profile, light/dark/system theme, reduced motion, selection mode/nudge distances, task notification preferences, model/access defaults, personal instructions and local activity counts.
- Templates/views: three original editable document templates; named page/zoom/position views stored in documents and shared rooms.
- Canvas: text, rectangles, nested frames, images, four authored SVG icons, pages, layer search, multi-select, snapping, alignment, scaling, z-index, zoom/pan and keyboard nudges.
- Layout/style: free/flex/grid/block/inline layout, typography, mixed text ranges, gradients, gradient masks, color variables and CSS color token import. Authored Aurora/Waves/Noise/Ribbon/Mesh/Swirl WebGL shader presets expose color/speed/intensity, with rendered GPU pixels and exported shader runtime tested. Separate animated CSS gradients remain available.
- Precision/export: rotation, opacity, frame clipping, borders/shadows, color picker/hex input and selected-artwork PNG/JPG/SVG export. SVG uses foreignObject rather than pure vector paths.
- Documents: undo/redo, local persistence, JSON round-trip, inline HTML import/export, responsive sandboxed preview, native PDF export. Native file open/save/watch shares the document format with MCP and rejects stale writes.
- Code workspace (Design/Code switch): full-window layout with a repositories/chats sidebar (add local folder, new project, GitHub clone; archive; quick chats; dismissible Next steps), breadcrumb chat switcher, Start preview split button wired to the dev server, the chat transcript and composer in a 770px column, a files panel (All/Changed files tree with change markers, file editor, project memory) and the terminal panel slot. Each repository chat gets its own git worktree and `verynize/<name>` branch; the active project (files, Changes panel, dev server, agent cwd) follows the active chat. See tests/code-workspace.cjs and tests/repositories.cjs. Publishing a preview to the web and inviting teammates reuse the existing local preview and cloud share flows.
- Projects: select a folder, inspect/edit text files, project memory, real Git worktree creation. New project and GitHub clone actions are implemented; public-network clone behavior has not been end-to-end tested.
- Agents: installed Claude/Codex discovery, explicit task execution, output streaming, queue/stop controls, file/canvas prompt context, review prompt. Both actual installed CLIs returned VERYNIZE_OK and exited 0 in isolated temporary projects without reading or modifying files. General code-editing success remains task/provider dependent. Provider/model/effort/access controls, persistent quick-chat task history and canvas attachments are implemented. CLI account status and explicit sign-in/cancel/sign-out adapters have deterministic subprocess tests; real account mutation/browser completion was not exercised.
- Preview/capture: embedded responsive localhost app pane and separate native window. Embedded capture reads the actual named iframe without a reload, preserving current DOM/input state and excluding passwords. Bounded capture preserves supported hierarchy, text/style, borders/shadows and eligible same-origin bitmap images. API region clipping, foreign-resource blocking, script exclusion and generated PDF bytes have Electron tests; the UI captures the viewport. Preview setup now originates from the chat LLM through `propose_preview`: persisted Setup/Run/Port proposal, inline Edit and Save & start review, pending/saved states across reload. Acceptance creates a persistent canvas frame with repository/chat linkage, paused/setup/running/error states, setup logs and process-group cancellation. Frame navigation, reload, path, expand, Navigate/Edit/Capture operate on the live iframe; DOM edits are transient until captured as design layers. Canvas rerenders retain live input state; reopening restores a paused frame without starting code. The Code and Design chat headers share Start/Stop controls. Tests cover real MCP proposal review, persistence, lifecycle, root boundaries and capture. Live application deployment/publishing and full Wonder visual parity have not been verified. Selected previews expose a fixed Navigate/Edit/Capture toolbar above the canvas toolbar, with input forwarding (Command/Ctrl+Shift+Escape releases it) and Open in browser using the current frame URL. Server detection supports npm/pnpm/Yarn/Bun declarations and lockfiles, plus plain index.html projects served by an available Python interpreter; no Vite+ dependency is required. Reference: `docs/wonder-preview-reference.md`.
- Headless automation and live MCP: 49 shared tools (Wonder-style design context, Tailwind-JSX element code, create_artboard, update_elements directive scripts, tokens, documents/pages, screenshots) served by a loopback, bearer-authenticated HTTP bridge inside the desktop app that edits the open canvas live with undo, and by the stdio server, which proxies to the bridge or falls back to on-disk documents. See wonder-ai-mcp-spec.md and tests/mcp-live.cjs.
- Canvas interactions: infinite cursor-anchored camera, tool modes with draw-to-create and frame presets, marquee/drill-in/keyboard navigation, smart guides with equal-gap snapping and distance lines, clipboard and style paste, frame/unframe, auto layout, z-order, lock/hide, Fixed/Hug/Fill sizing and a context menu. See wonder-canvas-spec.md and tests/canvas-interactions.cjs.
- Chat runtime: Claude Agent SDK sessions (streaming, resume, interrupt, permission cards) and Codex app-server threads, four access levels, quick-chat scratch folders, per-turn selection context and automatic wiring to the live MCP bridge. One real turn each through the Claude Agent SDK runtime (`claude-haiku-5-5`) and Codex app-server (`gpt-6-luna`) returned VERYNIZE_OK with the expected event stream, usage and MCP bridge tool discovery (tests/agent-runtime-live.cjs, opt-in via `npm run test:agents:live`). Rewind forks the provider session at the kept turn (Claude resumeSessionAt + forkSession, Codex thread/fork), falling back to a transcript seed; second opinion sends the latest answer and diff to the other provider, read-only. Rewind and second opinion have not been run live from inside the app.
- Collaboration: private capability rooms, persisted SQLite snapshots, WebSocket updates, names/cursors, reconnect, explicit conflict choice. Two real Electron clients exercised these against local workerd.
- Publishing: frozen read-only snapshots, access checks, unpublish/revocation. Tested locally, not deployed.
- Cloudflare: cf build/deployment dry run passes with Durable Object and rate-limit bindings. No production deployment occurred.
- Better Auth foundation (phase 0): email + password accounts, required email verification, password reset, bearer-only sessions and organizations with invitations, stored in D1 (`cloud/auth.js`, `cloud/migrations`). Verified on local workerd by tests/cloud-auth.mjs. Phase 1: the desktop signs in with email + password (sign-up, verification, forgot password through server pages), and Better Auth sessions act through the directory account with the same verified email, so rooms, invitations, profiles, passkeys and apps keep working (tests/cloud-auth-bridge.mjs, tests/cloud-account-pages.mjs, tests/cloud-accounts-desktop.mjs). Phase 2: rooms of email accounts belong to Better Auth organizations in D1 (personal organization by default). Organization owners and admins are room owners, members get the organization default role, and changes reach live sockets (tests/cloud-orgs.mjs). Phase 3: the desktop has a first-run onboarding (account sign-in/registration, then Claude/Codex agent connection), a Files workspace switcher with organization creation, Settings › Members (invitations, roles, default room access, incoming invitations, leave/delete) and workspace display/move in Share (tests/desktop-onboarding.mjs, tests/desktop-workspaces.mjs). Phase 4: profiles, the room membership index, publications and apps moved to D1 with an automatic, idempotent one-time copy from `AccountDirectory`, which now keeps only credentials (tests/cloud-directory-migration.mjs). Direct room members stay in each room's Durable Object. Real email delivery and a live D1 database are unverified.

- Illustration generation: actual Codex produced a valid SVG through the app generation service. SVG sanitization and PNG/raster tracing are tested in Electron. Raster tracing emits real quantized vector paths, not embedded images.

- Agent shell tools (bridge-only, 15): dev server detect/start/stop/saved command with process-group cleanup, embedded-preview open/outline/screenshot/real click·type·scroll/console/capture-to-canvas, terminal commands (argv, timeout, background read) and `execute_action` over the editor command registry. ## Design workflow audit — 30 October 2026

A new Wonder design was built through native desktop UI controls, with all five variable types, shared spacing bindings, SVG color/opacity bindings, flex/grid layout and effects experiments. The [workflow record](wonder-design-workflow-2026-10-30.md) distinguishes applied behavior from menus only observed and configurations still untested. A native 2× PNG and an editable Verynize recreation accompany the evidence.

Implemented and exercised in Verynize:

- Per-corner radius and per-side border width editors, mixed uniform values, binding removal on individual edits, scalar override cleanup, undo/rebind and rendered CSS checks.
- Color detach preserves each selected layer's effective paint and alpha; color creation rejects invalid/colliding names; CSS variable export reports ambiguous identifiers; malformed SVG insertion fails without adding a layer.
- Simple monochrome imported SVG tint and color-variable binding paint the shape independently of its background. Original source, alpha, multi-selection detach, reload, HTML export and JSX round trip are covered. Complex/multicolor SVG and catalog icon recoloring use different paths and are not covered by this control.
- Native export applies scale after navigation. Explicit artwork pixels and layout measurements pass at 0.5×, 1×, 2× and 4×; the prior output could have scaled dimensions with unscaled artwork.

Validation for this change: integration tests 116/116; codec fidelity 26 fixtures and 105/105 checks; inspector variable-library/binding, canvas-page, inspector-parity and native render-export Electron suites; syntax/asset checks, UI lint and TypeScript checks. This is targeted validation, not a rerun of every unrelated desktop/cloud suite.

## Remaining gaps and live-credential boundaries

- Needs live credentials or infrastructure, so verified only against local fixtures: real Figma OAuth and data, real image-provider APIs, real provider browser login and named-account plan limits, email delivery, production sign-in, a separate apps domain for full origin isolation. Touch ID/iCloud passkeys in Electron are unverified.
- The Figma decoder uses field names from public sources and has not yet seen real Figma clipboard data.
- Capture: no `@keyframes`, pseudo-elements, shadow DOM, iframes or off-viewport content; interaction variants are stored as metadata without an editing UI.
- Codec: page scripts are not executed; `::before/::after`, `float`, relative offsets and some background options are reported as warnings rather than represented.
- Inspector: no on-canvas mask handles or editable mask stops, picker shader previews are static, no Wonder-style single border-side selector, and agent `update_elements` on bound properties is reverted by the next binding sync.
- Merging is server-sequenced rather than peer-to-peer CRDT. Published apps run sandboxed without cookies/localStorage.
- `npm run package:mac` was not rerun after adding `@vscode/ripgrep`.
- Known flaky tests that also fail on a clean HEAD: `tests/capture-live-state.cjs` (intermittent preview reload) and `tests/mcp-shell.cjs` (preview click).
