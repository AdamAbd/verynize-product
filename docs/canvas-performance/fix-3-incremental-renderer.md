# Fix 3: incremental canvas renderer (2026-11-05)

Branch `perf/incremental-dom-renderer`, stacked on `docs/perf-research` (PR #12). Scope: fix 3 of the [plan](README.md#measured-gains-ranked-by-cost-to-implement) ("no `render()` during live drag; keyed per-node patches") and the first steps of the optimized DOM renderer (strategy B in [renderer-options.md](renderer-options.md)). Out of scope here (other agents): the five `:has(:focus-visible)` rules (fix 1), `drawFrameLabels` and the selection algorithms `descendants` / `topSelected` / `rows` (fixes 2–3), and any tile or Canvas 2D layer.

## What changed, per stage (one commit each)

| Stage | Commit                                                     | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | `perf: move dragged layers without rendering the document` | `startMove` (`web/canvas-interactions.js`) no longer calls `render()` per pointer move. Dragged free layers follow through a CSS `translate` on their own element (parent space, so it composes with rotation and a centred constraint's own translate); x/y still change live, so snapping, guides, drop targets, agents (`getDocument`) and the name label read the live position. One render and one undo step at release. Nesting into a frame on the way still renders once and re-measures the offset; a render from elsewhere during the drag (collaborator, agent) is detected and the offset re-based. Alt-drag renders its copies once before they follow.                                                                                                                                                                                                                                                                                                                                                  |
| 2     | `perf: keyed incremental canvas renderer`                  | New `web/canvas-render.js` (loaded before `app.js`). One element per node id, kept across renders. Each render compares every node with what its element last drew (own fields; parent layout; selection; last-in-flow; variables) and redraws only the elements that differ, **in place** (attributes and own content reset and redrawn; child layers moved, never rebuilt). Order, parent and type changes move elements; deletions remove theirs. Shaders start after placement and keep running on untouched layers. A `MutationObserver` marks elements written by other code (text editor, drag offsets, inspector colour previews, shader fallback) for a redraw on the next render, which is what the full rebuild did for them. Live previews keep their own element as before. `layerElement()` still builds detached trees for export. `app.js`: `layerElement` delegates, `render()` calls `canvasRender.render()`, and the sizing pass looks parents and elements up by id instead of scanning the page. |
| 3     | `perf: cheaper one-node commits`                           | Subscribers declared without a parameter get no document clone (6 of the 13 in the app); `updateNodes` checks image limits on the edited nodes only (equivalent, since nothing else changed) and still runs the full storage check when they add images; `save()` serializes once the editor is idle (≤ 200 ms) and flushes on `pagehide` / hidden visibility, with the document-safety hold and cloud-account rules applied at both points. Validation is unchanged: a shallow-copy variant was measured and was not faster (validation itself dominates), so the deep clone stays.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 4     | `perf: cull offscreen artboards`                           | Top-level frames that clip their content and have a fixed size, more than half a viewport outside the view, get `data-culled` → `content-visibility: hidden` (`web/canvas.css`). Their own box stays laid out and painted (frame labels, fit, marquee); their subtree skips style, layout and paint. Layout queries inside a culled board still return exact geometry (Chromium lays it out on demand; verified: rects, hug widths, export). A grid index (2048 world px cells) finds boards near the view; boards hide at once, and come back immediately on a camera jump or render, or at most 6 per camera step (nearest first) during a wheel/drag gesture, then all once it settles (150 ms). `localStorage['verynize.canvas-cull'] = 'off'` turns it off. `will-change` was already limited to pan gestures (zoom is never promoted, for tile memory: `tests/canvas-compositing.cjs`), so it is unchanged.                                                                                                     |

Switches (both in `localStorage`, read on every render): `verynize.canvas-render = full` restores the full rebuild (the regression test uses it as the reference), `verynize.canvas-cull = off` disables culling.

## Measurements

Same harness and fixture as the [baseline](verynize-baseline.md) (`eval/canvas-perf/bench-verynize.cjs`, seed 241104, 5% top-level frames, real Electron, production handlers), Apple M1 8 GiB, **3 runs per size** (medians; with 3 samples p95 is the maximum). Other agents were benchmarking on the same machine: one-minute load averages are recorded per run in each JSON (`samples[].machine.loadAverage`) and summarised below. The lead should rerun sequentially on an idle machine before treating cells as final.

New harness options used here: `--skip selectAll` (all-node selection is agent 2's area and hits the 60 s ceiling at 2,000, which stops the run), `--strip-has` (removes the five `:has(:focus-visible)` rules through CSSOM before the document loads, as `experiment-has.cjs` does: fix 1 simulated), `--storage verynize.canvas-render=full,verynize.canvas-cull=off` (the old full rebuild in the same build, for an A/B), `--clip-boards` (top-level frames clip their content, so culling applies).

## Where an edit's time goes now (CPU profile, 1,000 nodes)

`node eval/canvas-perf/profile-edit.cjs 1000 [--strip-has] [--full]`: 10 one-node edits (`design.updateNodes(['n1'], {color})`) on the benchmark fixture with the sampling profiler running (0.2 ms), per-edit inclusive time, one run each, final build:

| Variant                                           |   Edit sync | `drawFrameLabels` | Legacy hidden rows (`rows` + `render()` self) | Canvas renderer (`canvas-render.js`) | `validate` |
| ------------------------------------------------- | ----------: | ----------------: | --------------------------------------------: | -----------------------------------: | ---------: |
| Full-rebuild switch, `:has` rules present         |    248.0 ms |          162.2 ms |                                        ~42 ms |                              24.5 ms |     4.2 ms |
| Keyed, `:has` rules present                       |    224.1 ms |          160.3 ms |                                        ~42 ms |                               1.8 ms |     4.0 ms |
| **Keyed, `:has` rules removed** (fix 1 simulated) | **71.4 ms** |        **8.2 ms** |                                        ~41 ms |                               2.0 ms |     4.1 ms |

The renderer itself now costs about 2 ms per edit at 1,000 nodes (24.5 ms for the full rebuild). The larger effect is indirect: `drawFrameLabels` forces one style recalculation per top-level frame (50 here), and each costs in proportion to what is dirty. With the `:has(:focus-visible)` rules present every recalc walks the whole canvas whatever the renderer does (160 ms); without them, a keyed patch leaves one element dirty and the 50 recalcs cost 8 ms. **Fix 1 and this fix compound**: the benchmark (no profiler) gives 214 ms with this branch alone, 101 ms with fix 1 alone on this build (full-rebuild switch), and 72 ms with both (table 2). (Profiling the full-rebuild switch with the `:has` rules removed gave 222 ms against 101 ms in the benchmark: the profiler inflates that variant, so it is left out of this table.) Fix 2 (labels positioned from document geometry) removes the remaining label cost; the largest item left after that is the hidden legacy layer-row rebuild on every render (~41 ms: `rows`, agent 2).

## What remains for full strategy B

| Item                                                                       | State after this branch                                                                                                                                     | Next step                                                                                                                                                                                 |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keyed per-node patches                                                     | Done for every render path (edits, selection, undo/redo, MCP, cloud, page switch)                                                                           | Replace the per-render O(N) comparison (~2 ms at 1,000 nodes) with dirty marks: the legacy editor mutates nodes in place, so this needs a mutation API (or proxies) first                 |
| No render during gestures                                                  | Move-drag only                                                                                                                                              | Resize, rotate and spacing drags (`selection-chrome.js`, `startSpacing`) still render per pointer move; the same follow/commit pattern applies                                            |
| Culling                                                                    | Fixed-size top-level frames that clip their content                                                                                                         | Unclipped or hugging boards need paint bounds (union of descendant boxes, effect outsets) before they can be culled; shaders inside culled boards keep animating (stop them while culled) |
| Budgeted mounting                                                          | Count budget (6 boards per camera step) during gestures, everything on settle/render                                                                        | A time budget with a completeness signal (share of near boards still culled) so incomplete content can be measured, as the astra review asked                                             |
| `contain`                                                                  | `content-visibility: hidden` (implies size, layout, paint and style containment) on culled boards only                                                      | `contain: strict` on visible boards changes painting (overflow clipping, stacking) for unclipped boards; worth measuring only on clipping boards                                          |
| `will-change`                                                              | Already only during pans (zoom never promoted: tile memory)                                                                                                 | Unchanged                                                                                                                                                                                 |
| Selection chrome in a screen-space overlay instead of the inherited `--iz` | Not started                                                                                                                                                 | Writing `--iz` on `#canvas` restyles every layer on zoom; overlay chrome would remove that                                                                                                |
| Thumbnails below 8% zoom                                                   | Out of scope (Canvas 2D: agent 4)                                                                                                                           |                                                                                                                                                                                           |
| Other render work                                                          | Legacy hidden rows (~58 ms at 1,000), `drawFrameLabels`, 7 subscriber deep clones (101 ms at 5,000), whole-document validation and undo snapshot per commit | Agent 2 (rows, labels); immutable snapshots or structural sharing for islands; patch-based undo history                                                                                   |
