## Recurring claims to test

1. DOM canvases fall apart at a few hundred (Jesse) or 2-5K (Amichai) layers, against 13K–100K+ in real files.
2. The cost is style recalculation and layout per pan/zoom, not Chromium itself (Jesse), or forced layout per drag (sebuzdugan).
3. Virtualising offscreen nodes, proxies for heavy content and per-node caches are enough for DOM (Shane, adircode, dt_sqr, Vlad).
4. A tile-based Canvas 2D renderer is simpler than WebGPU and keeps DOM-consistent text metrics (Whimsical).
5. Agents generate better designs in HTML/CSS (samlibo, notionsmith, deepit_patil), and keeping the file format HTML/CSS does not require a DOM renderer (Daafdaan, Penpot).
6. Text input, IME, spellcheck and accessibility should stay in the DOM (safelibra, danscriptscript).
