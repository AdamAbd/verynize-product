# Desktop workflow contract

`window.desktop` is exposed by the sandboxed preload. Every main handler checks the window, main-frame identity and the sender's origin (`app://verynize`). No raw IPC or Node objects reach the renderer.

**Renderer contract.** `web/src/lib/desktop-api.ts` (`DesktopApi`, `DESKTOP_API_SHAPE`) is the typed copy of everything `preload.cjs` exposes; `tests/platform-contract.cjs` (in `test:desktop`) fails when the preload and that type disagree, so a new preload method lands together with its type. The renderer never feature-detects `window.desktop` itself: `web/platform.js` (loaded first by `web/index.html`) derives `window.verynizePlatform` = `{kind: 'desktop'|'web', desktop, capabilities, can(name)}` from it, with each capability mapped to the preload methods it needs (`CAPABILITY_METHODS`). Islands import it from `@/lib/platform`; legacy scripts check `verynizePlatform.can(...)` before calling `window.desktop`. See "Desktop vs web runtime" in `web/src/islands/README.md`.

- **App protocol** (`desktop/app-protocol.cjs`). The editor loads from `app://verynize/index.html`, a privileged standard, secure scheme (`supportFetchAPI`, `corsEnabled`, `stream`, `codeCache`), not `file://`. The handler serves files from `web/` only: each path segment is decoded and refused when it holds `..`, a separator (`%2f`, `%5c`), NUL or `:`; dotfiles, missing files and symlinks resolving outside `web/` get 4xx with no file content. Any extensionless path (`/editor`, `/projects/x`) is a client-side route and returns `web/index.html`, so `index.html` references its assets root-absolute (`/app.js`). IPC is accepted when the sender is the window's main frame and its origin is `app://verynize`; path, query and hash do not matter. `will-navigate`/`will-redirect` allow same-origin `app://verynize/*` and block everything else.
- **Storage origin migration** (`desktop/storage-migration.cjs`). Moving from `file://` to `app://verynize` changes the storage origin, so localStorage (documents and file library, chats, settings, cloud sessions) and the `verynize-cloud` IndexedDB outbox would start empty. Before the first window opens, the old `file://` storage is copied once into `app://verynize` through a hidden window (keys already present are kept; the `file://` data is left untouched). `userData/storage-origin-migration.json` is written as `{pending: true}` before the copy and replaced by the result afterwards. A pending record on a later launch means the copy failed or crashed and the editor ran on an empty origin, writing first-run defaults (an empty file library, default settings); that retry lets the `file://` values win over those defaults and saves every replaced `app://` value to `userData/storage-origin-migration-replaced.json`. It gives up after three failed attempts. Profiles with no `file://` rows skip the window.

- `openProject()` uses the native folder picker and returns `{root,name,repoId}` or null; the folder is also added to the repository list. `createProject({name,repository?})` makes a new git project or HTTPS GitHub clone in a picked parent folder and opens it the same way.
- **Repositories and chat worktrees** (`desktop/repositories.cjs`, the Code workspace). `window.desktop.repositories`:
  - `list()` → `{repositories:[{id,name,root,addedAt,git}], active:{root,repository,worktree}|null}`. The registry is `userData/repositories.json`; `git` is true for the top level of a repository with a commit.
  - `addLocal()` (folder picker), `create({name,repository?})` (new git project or HTTPS GitHub clone inside the Verynize folder, Settings › Agents) → repository or null. Re-adding a root returns the same id.
  - `archive(id)` hides a repository from the list; files, worktrees and chats stay (re-adding restores it).
  - `createChatWorktree({repoId,chatId})` → `{path,branch,shared}`: `git worktree add -b <prefix>/<name> <workspaces>/<repo>/<name> HEAD`, where `<workspaces>` is `<Verynize folder>/workspaces` (default `~/Verynize/workspaces`; `VERYNIZE_WORKSPACES_DIR` overrides it, used by tests) and `<prefix>` is the Settings › Agents branch prefix, else `VERYNIZE_BRANCH_PREFIX`, else the `gh` GitHub username, else `verynize`. Existing worktrees keep their recorded path and branch. Idempotent per chat. A folder that is not the top level of a committed repository returns `{path:root,branch:null,shared:true}`: the chat works in the folder itself.
  - `removeChatWorktree({repoId,chatId,force?})` runs `git worktree remove` (refuses uncommitted work unless `force`); the branch is kept.
  - `activate(root|null)` (main-side *setActiveRoot*) makes `root` the window's active project for `listFiles/readFile/writeFile`, memory, `gitStatus`, the Changes panel, the dev server and shell tools. Only registered repository roots and worktrees recorded by `createChatWorktree` are accepted (compared after realpath); `null` clears it (quick chats). It does not refuse while agents run: each run keeps its own cwd.
  - `runAgent({root})`: the chat's folder (worktree or repository root), validated the same way; `root:null` runs in the quick-chat scratch folder. Without `root` the active project is used, as before.
  - Git runs as `execFile` argument arrays with timeouts and `GIT_TERMINAL_PROMPT=0`; mutations are serialized.
- **Agent behaviour** (`desktop/agent-behavior.cjs`, Settings › Agents lower half; stored in `userData/agent-behavior.json`). `window.desktop.agentBehavior`:
  - `get()` / `set(patch)` → `{followUp:'queue'|'steer', expandWork, claudeOutputStyle:''|name, codexPersonality:'default'|'none', creditAgent, folder, branchPrefix, repoModes:{repoId:access}, displayFolder, defaultFolder}`; `set` validates (branch prefix must be a valid ref path; `repoModes[id]=null` resets to the Default). `chooseFolder()` opens a folder picker and saves it.
  - The runtime reads it per run: a chosen Claude style and credit off become SDK `settings` (`outputStyle`, `attribution:{commit:'',pr:''}` + `includeCoAuthoredBy:false`; CLI fallback `--settings`); Codex personality None becomes `thread/start` `personality:"none"` (exec fallback `-c personality="none"`).
  - `outputStyles()` → `{styles:[{id,name,description,source}], current}`: built-in Default/Explanatory/Learning plus `~/.claude/output-styles/*.md`; `current` is `outputStyle` from `~/.claude/settings.json`.
  - `commitAuthor()` → `{name,email,login,linked}` from `git config --global` and `gh api user` / `gh api user/emails` (`linked:null` when gh is signed out or lacks the email scope).
  - `allowList()` → groups `{id,agent:'verynize'|'claude'|'codex',scope,global,file,rules:[{id,title,raw}]}` from Verynize's `agent-allow-rules.json`, Claude Code `permissions.allow` (`~/.claude/settings.json`, `<repo>/.claude/settings{,.local}.json`) and Codex `prefix_rule(...)` lines (`~/.codex/rules/*.rules`, `<repo>/.codex/rules`). `allowRemove(ruleId)` removes exactly that entry (Codex: the rule text and its line break; Claude: one array element, indentation kept); `allowOpen(groupId)` opens the group's file. Ids are opaque: the renderer never names a file.
- `devServer.status()`, `devServer.start()`, `devServer.stop()` control the active project's dev server (`desktop/dev-server.cjs`, same process manager as the agent shell tools) for the Code workspace "Start preview" button. These are user actions, so no approval dialog; `start` first runs a saved setup that changed or did not finish (`status().setupPending`), then waits up to 20 s for the URL. `status({root, tail})` returns up to 400 log lines (default 30) for the frame terminal; a new `start` drops the previous run's exit record so its old failure is never reported for the new attempt. `devServer.configure({root, commands:[{name,command,url?}], setup?, stop?})` saves the Preview settings: every start command runs together and the first one with an Opens at `url` (else the first) gives the preview address; `setup`/`stop` are one argv or a list of argv steps (`a && b`, run in order). `stop()` also stops the extra commands and then runs the stop command (own process group, 60 s timeout). An agent `propose_preview` is saved directly as this configuration in auto/full access (never started) and becomes a review card in ask/edit.
- `previewClearData({url, logins})` clears the embedded preview's site data for the localhost origin of `url` (local storage, IndexedDB, Cache Storage, service workers, file system; `sessionStorage` in the page) and reloads the frame when it shows that origin. `logins: true` also clears cookies; cookies are host-scoped, so this covers every port on that host. Used by the preview frame's canvas context menu.
- **Canvas preview frame** (`web/live-preview.js`, `web/preview-frame-chrome.js`): `previewNavigate({direction, ignoreCache?})` runs back/forward/reload in the embedded frame (`ignoreCache` clears that origin's HTTP cache first, for ⇧-click Reload); `onPreviewNavigated(callback)` reports `{url}` whenever the frame navigates (links, redirects, `history.pushState`), so the toolbar path and Back/Forward follow in-app navigation.
- **Web page capture** (`desktop/capture-remote.cjs`, `desktop/capture-core.cjs`). `captureRemoteProbe({url,width?,height?})` → `{screenshot,boxes,width,height,title,url}` for the region picker; `captureRemote({url,width?,height?,region?,interactions?})` → `{document,html,warnings,region}`. Any http(s) URL without credentials; the page loads in a hidden window with a fresh in-memory session partition, sandbox, no Node and no preload (scripts run so the page renders); permissions, popups, downloads and non-http(s) navigation/requests are refused. Cross-origin images, CSS backgrounds (→ `fills` image paints) and the @font-face fonts used by captured text (→ document `fontFaces`, data URLs) are embedded (2 MB per asset, 8 MB images, 6 MB fonts). Every node gets `capture.source` `{url,selector,xpath}` plus `dev:{file,line,column,via}` on localhost pages (data-source*/inspector attributes, React dev fiber, Vue `__file`); interactive elements get `capture.states` (`hover`/`focus`/`focus-visible`/`active` computed-style deltas forced through the DevTools protocol, with child restyles), `capture.transitions` and readable `capture.notes`. `previewApp({capture:true})` records the same source and states for localhost apps; `captureLivePreview` adds source mapping (no state probing in the live iframe). `previewElementAt({x,y})` returns the element box under a point of the embedded preview for the live region picker.
- **Running-app preview frames** (`desktop/preview.cjs`). `previewNavigate({direction,target?})`, `previewElementAt({x,y,target?})`, `captureLivePreview({url,region?,target?})`, `previewOpenBrowser({target?})` and `previewLocation({target?})` → `{url}` act on the canvas iframe named `verynize-live-preview` by default, or on the expanded preview tab's iframe `verynize-preview-tab` with `target:'tab'`. Both frames must show a localhost URL. Agent automation only ever drives the canvas frame.
- **Preview Edit / Capture modes** (`desktop/preview-dom.cjs`, renderer `web/preview-edit.js`). `previewDom({op,…})` runs one fixed in-page function in the embedded preview: `at {x,y}` / `describe {path}` / `relative {path,dir}` return an element description (structural path, agent ref, tag, text, box, sizing, computed layout/typography); `apply {ops:[{path,kind:'text'|'style',prop?,value}]}` writes staged edits to the live DOM (allow-listed style properties, `CSS.supports`-checked values, no `url()`); `textStart {path,x,y}` / `textEnd` run direct `contenteditable=plaintext-only` text editing. Edits are transient and never written to source files.
- **Image model providers** (`desktop/generate.cjs`, `integrations/image-provider.mjs`). `imageProvider.get()` → `{provider:'openai'|'http',baseURL,model,size,hasKey,keyStorage:'keychain'|'session'|'none',secureStorage,configured}` (never the key); `imageProvider.set({provider?,baseURL?,model?,size?,apiKey?,clearKey?})`; `imageProvider.generate({prompt,size?})` → `{src,mime,width,height,provider,model}` (PNG/JPEG/WebP verified by magic bytes). Settings are `userData/image-provider.json`; the key is stored only as `safeStorage` ciphertext (session memory when OS encryption is unavailable), sent only as the Bearer header, redacted from provider errors and never logged. Base URLs must be https (http only for loopback). `cancelGeneration()` also aborts an image request. Live providers need a live credential; tests use local fixture servers.
- **Publish app** (`desktop/app-publish.cjs`, Share › Publish app). `cloudAppDetect()` → `{root,name,title,hasBuild,command,packageManager,outputDir}` for the open project. `cloudAppPublish({server,session,name?,title?,outputDir?,build?,note?})` runs the project's own `build` script (argument array, no shell, 10 min timeout; Vite/Vite+ builds get `--base=./`), collects the output folder (needs `index.html`; ≤3000 files, ≤25 MB per file, ≤100 MB), uploads it to the cloud Worker with the account session and seals a new live version → `{version,files,bytes,url,versionUrl,app,outputDir,log,built}`.
- **Passkeys** (`desktop/cloud-passkey.cjs`, Share › Account). `cloudPasskeyOpen({url})` opens `<server>/passkey#…` in a small window (no preload, in-memory `verynize-passkey` session, sandboxed, navigation locked to the server origin, popups denied) because the local `app://verynize` renderer is not on the server's origin and cannot be its WebAuthn relying party; `cloudPasskeyClose()` closes it. The renderer claims the resulting session through the Worker's handoff endpoint.
- `listFiles()` returns up to 2,000 `{path,size}` entries, depth at most eight; excludes symlinks, .git, node_modules, and common build output.
- `readFile(path)`, `writeFile(path,text)` accept relative, existing-parent paths within the chosen project. .git, traversal, absolute paths, symlinks, binary reads, and files over 2 MB are rejected. File writes are explicit user actions; external concurrent filesystem changes are not locked.
- `gitStatus()` returns git short branch/status output. `createWorktree('design/name')` creates a new branch and sibling directory; requires a committed Git repository, never overwrites an existing directory or branch. Return `{path,branch}`. Select that directory separately to edit it.
- **Changes panel** (`desktop/git-changes.cjs`, the design → code loop). Every call takes `{root?}`. `root` defaults to the open project, and it must be the project root or one of its registered `git worktree list` entries (compared after realpath). The root must also be the repository top level. Commands run as `git`/`gh` `execFile` argument arrays (no shell) with timeouts, `GIT_TERMINAL_PROMPT=0`, literal pathspecs and `GH_PROMPT_DISABLED=1`. Errors carry readable messages: git/gh missing, not a repository, gh signed out, identity missing, push rejected/auth/network.
  - `gitChanges({root?})` → `{root,branch,detached,head,upstream,upstreamBranch,ahead,behind,remote,remoteUrl,files:[{path,status,code,added,removed,binary}],totals:{files,added,removed},truncated}`. `status` is one of modified|added|deleted|untracked|conflicted. Counts are numstat against HEAD (the empty tree in a fresh repository); untracked text files under 2 MB are line-counted. The list stops at 1,000 files. Credentials are stripped from `remoteUrl`.
  - `gitBranchChanges({root?})` → `{root,base,files:[{path,status}],truncated}`: every file the branch changed since it left the default branch (merge base of HEAD with `origin/HEAD`, `main` or `master`; `base` names that ref, or is null when there is none), its commits plus uncommitted and untracked files. The Code workspace file tree's "All changes" filter.
  - `gitDiff({root?,file})` → `{file,status,diff,truncated,binary}`: a unified diff (`--no-index` for untracked files), cut at 512 KB. `file` must be in the current change list.
  - `gitCommit({root?,message})` runs `git add --all` then `git commit -m` (hooks run, never amends) → `{commit,branch,message,files}`.
  - `gitDiscard({root?,file})` restores a changed file from HEAD, or deletes it when it is new or untracked. The UI asks for confirmation first.
  - `gitPush({root?})` pushes `refs/heads/<branch>` to its upstream, or publishes the branch with `--set-upstream` to `origin` (else the first remote). It never forces → `{branch,remote,upstream,summary}`.
  - `gitPullRequest({root?})` → `{gh:'ready'|'missing'|'unauthenticated'|'unsupported', pr:{number,url,state,title,isDraft,base,head}|null, message?}` via `gh pr view <branch> --json`.
  - `gitCreatePullRequest({root?,title?,body?,base?,draft?})` runs `gh pr create --head <branch>` with `--fill`, or `--title/--body` when a title is given. The branch must be pushed with no unpushed commits. An existing PR is returned with `existed:true`.
  - Mutating calls are serialized per repository.
- **Settings › Preferences** (`desktop/app-preferences.cjs`). `window.desktop.appPreferences`:
  - `chooseSound()` opens the native picker (MP3 only, up to 8 MB, checked for an ID3 tag or MPEG frame sync) and copies the file to `userData/sounds/custom.mp3` → `{name,size}` or null. `readSound()` → bytes or null; `clearSound()`.
  - `linksReady({enabled})` marks the window ready for `verynize://` links and drains links that arrived earlier (macOS `open-url`, or argv elsewhere) → `{enabled,registered,reason?,pending}`. `setLinksEnabled(bool)` calls `app.setAsDefaultProtocolClient('verynize')` / `removeAsDefaultProtocolClient`. Unpackaged builds only register with `VERYNIZE_REGISTER_PROTOCOL=1`; the packaged app declares the scheme in `CFBundleURLTypes`. `onOpenLink(callback)` receives links while enabled. Supported links: `verynize://node/<document>/<page>/<element>` (selects and zooms) and `verynize://join?invite=<https invite URL>` (share dialog, asks before joining).
  - `worktreeLineStats(roots)` → `{[root]:{added,removed,files}|{error}}`: uncommitted numstat totals, for registered repository roots and chat worktrees only.
- `readMemory()`, `writeMemory(text)` use project `VERYNIZE.md`. This file is not automatically injected into agent prompts.
- `renderPDF({html,width,height})` prints the artwork HTML to a one-page PDF of exactly that CSS size (fonts embedded like `renderDesign`) and returns `{dataURL,width,height,bytes}`. `saveExport({name,data,extension})` shows the native save dialog (default folder Downloads) and writes `data` (a base64 data URL or text) for `png|jpg|webp|svg|pdf|html|css|jsx`; returns `{path,name,bytes}` or null when canceled. `exportCode({flavor:'tailwind',document,pageId,nodeIds,name,snippet?})` returns `{content,extension:'jsx'}` (a React component through the JSX codec; `snippet:{links,date}` adds the clipboard form used by Copy as code and Copy prompt: a "Made with Verynize" comment, Google Fonts links and a box-sizing reset); `exportCode({flavor:'css',html,tokens})` returns `{content,extension:'html'}` with the artwork's inline styles moved into class rules (`integrations/export-code.mjs`). `renderDesign` accepts scales 0.01–100× as long as the output stays within 16384 px per side and 32 MP (page zoom up to 4×, CSS zoom beyond). `fontCatalog()` returns `{fonts:[{family,kind,category,weights,styles}],source}` from `integrations/fonts.mjs` (Fontsource list cached for a week, bundled fallback).
- `importHtml({html, document, pageId?, viewport:{width,height,colorScheme?}, allowRemote?, baseUrl?})` imports pasted HTML into `document` with `integrations/codec-html.mjs` (CSS cascade for the viewport, `:root` colour tokens and typed variables, Tailwind classes) and returns `{document, pageId, rootIds, warnings, stats}`. `importHtmlFile(sameOptions)` shows the native open dialog for an `.html` file and imports it with its stylesheets, `@import`s and images resolved relative to the file (only inside its folder; http(s) only with `allowRemote`); it returns the same plus `file`, or `null` when cancelled. Viewport 200–8000 px, HTML under 5 MB. Implemented in `desktop/html-import.cjs`.
- `discoverAgents()` detects Codex and Claude executables without executing models. Existing CLI authentication is reused only on execution.
- **Settings › Agents** (`desktop/agent-tools.cjs`), `window.desktop.agentTools`:
  - `accounts()` → `[{id,name,installed,loggedIn,comingSoon?,hint?,accounts:[{email,organization,plan,method,default}]}]` for Claude Code (`claude auth status --json`, `~/.claude.json` `oauthAccount`), Codex (`codex login status` + display claims of the `~/.codex/auth.json` id_token), Cursor and OpenCode (install detection only). Tokens are never returned or logged.
  - `listServers({agent,check?})` → `{agent,installed,servers:[{name,transport,target,command,status,detail,removable,source}],checked,error?}`. Claude: user-scope `mcpServers` in `~/.claude.json` and `~/.claude/settings.json`; Codex: `[mcp_servers.*]` in `~/.codex/config.toml`. `check` merges live status from `claude mcp list` / `codex mcp list --json` (`connected`, `needs-auth`, `error`, `disabled`, `pending`). Credentials in URLs and headers are redacted.
  - `addServer({agent,name,transport:'http'|'stdio',url?|command,args?})`, `removeServer({agent,name})` and `loginServer({agent,name})` run `claude mcp add|remove|login` (user scope) or `codex mcp add|remove|login`. Without the CLI, add/remove edit `~/.claude.json` or `config.toml` in place, keeping everything else.
  - `getAccess()` / `setAccess(changes)` read and merge the Access switches (`desktop/agent-access.cjs`, see `docs/agent-workflows.md`); turning Computer Use off returns `{stopped}` after cancelling Codex chats that had it.
- `runAgent({agent,prompt,chatId,model?,effort?,access?,sessionId?,instructions?,context?})` starts one chat turn (see `desktop/agent-runtime.cjs` and `docs/agent-workflows.md`). Claude runs through the Claude Agent SDK on the installed Claude Code; Codex through `codex app-server` JSON-RPC, falling back to `codex exec`. `access` is `ask|edit|auto|full`. Without a project the turn runs in `userData/agent-workdirs/<chatId>`. At most three turns run per window. `respondAgentPermission({requestId,allow})`, `listAgentModels({agent})` and `saveAgentImage({chatId,name,data})` support approval cards, the model picker and pasted images. `runAgent` also takes `directories` (extra working folders: Claude `additionalDirectories`, Codex writable roots); a prompt starting with `/name` is a slash command, sent to Claude as typed and expanded for Codex (custom prompts, skills).
- Composer "+" menu and slash commands: `listAgentCommands({agent,root?})` (`desktop/agent-commands.cjs`: SDK `supportedCommands()` plus `~/.claude/commands|skills`, `.claude/…`, `~/.codex/prompts|skills`), `designReferencesList()`, `designReferencesSave({name,images})`, `designReferencesAttach({id,chatId})`, `designReferencesRemove(id)`, `worktreeAddFiles({root,folder})`, `pickWorkingDirectory()` (`desktop/chat-attachments.cjs`), `terminalRecentOutput({cwd?})` (`desktop/terminal.cjs`).
- **Settings › Usage** (`desktop/agent-usage.cjs`). `agentUsage.read({agent:'claude'|'codex',refresh?})` → `{agent,status:'ready'|'signed-out'|'unavailable'|'missing'|'error',message?,email,organization,plan,limits:[{id,label,usedPercent,resetsAt?}],extraUsage?,credits?,resetCredits?,updatedAt}`, cached for 60 s unless `refresh`. Claude comes from the Agent SDK's structured `/usage` data and `accountInfo()` on the user's own `claude` login (no token is read by Verynize); Codex from a short-lived `codex app-server` (`account/read`, `account/rateLimits/read`). `VERYNIZE_DISABLE_AGENT_USAGE=1` turns provider checks off (tests). `agentUsage.layers()` → `{thisWeek,lastWeek,total,weekStart,resetsAt}`: nodes that MCP tool edits added to documents (`desktop/mcp-bridge.cjs`), per local week, in `userData/agent-usage.json`. No quota.
- **Composer indicators** (`desktop/agent-live-status.cjs`). `agentLiveStatus.mcp({agent,chatId})` → `{agent,live,servers:[{name,status:'connected'|'starting'|'failed'|'needs-auth'|'disabled'|'not-started',error?,builtIn?}],error?}`: while the chat's run is open, the agent's own report (Claude SDK `mcpServerStatus()`, Codex `mcpServerStatus/list`); otherwise the configured list (Verynize's `verynize` server plus the user's servers from config files, no CLI run), all `not-started`. During a run the same shape streams as `mcp-status` agent events (Codex events are `partial`: merge by name). `agentLiveStatus.context({chatId})` → `{totalTokens,maxTokens?,percentage?,model?,categories:[{id?,name,tokens,kind}]}` from Claude `getContextUsage({detail:'summary'})` while the run is open, else `null`.
- **Settings › Memory** (`desktop/agent-memory.cjs`). `agentMemory.overview()` → repo-less Claude memory folder and its files, Codex memories (`[features] memories` in `~/.codex/config.toml`; `~/.codex/memories` summary/skill counts), Claude user memory (`~/.claude/CLAUDE.md`, auto memory on/off and folder) and the home instruction files. `agentMemory.reveal({kind,name?})` shows a known folder/file in Finder; `agentMemory.open({kind,name?})` opens a known file in the default editor (instruction files are created empty on first open). Only fixed kinds are accepted (`repoLess`, `repoLessFile`, `codexMemories`, `claudeProjects`, `claudeAutoMemory`, `codexAgents`, `claudeUser`). `VERYNIZE_AGENT_HOME` replaces the home folder (tests).
- `onAgentEvent(callback)` returns an unsubscribe function. Events carry `{id, chatId, seq, type}` with types `session`, `status`, `assistant-text-delta`, `assistant-text`, `thinking-delta`, `tool-call`, `tool-input-delta`, `tool-result`, `permission-request`, `permission-resolved`, `usage`, `error` and a final `done {code, stopped, sessionId}`. `cancelAgent(id)` interrupts the turn (SDK `interrupt()` / Codex `turn/interrupt`, process kill for the fallback). Closing the window cancels its turns.

Validated with Context7 `/electron/electron` IPC/security documentation and installed `codex exec --help` / `claude --help`. Tests cover real temporary Git operations and file containment, plus Electron preload, discovery and renderer isolation. `node --test tests/repositories.cjs` covers the registry and worktrees against real temp repositories; `node tests/code-workspace.cjs` drives the Code workspace in Electron. No authenticated model request was run during implementation.

## Figma import adapter

One converter (`convertFigma` in `desktop/figma.cjs`) takes nodes in the shape of Figma's public REST API and produces a version-2 document. Three sources feed it:

- **REST** `importFigma({url, token} | {url, useAccount:true})` → `{document,warnings,source:{fileKey,nodeId}}`. `token` is a transient personal access token (`X-Figma-Token`, never stored); `useAccount` uses the connected OAuth account (`Authorization: Bearer`). Requests use `geometry=paths` so vectors, `size` and `relativeTransform` are available. Credentials go to `api.figma.com` only; image downloads carry no authorization, redirects are rejected and asset hosts are limited to Figma CDN/S3 patterns.
- **Clipboard** `figmaClipboard(html)` → `{format:'verynize/nodes', nodes, roots, tokens, warnings, source}`. Figma writes two marked base64 blocks into `text/html` (JSON metadata and a `fig-kiwi` binary scene). `integrations/figma-kiwi.mjs` (original kiwi schema/message codec, archive reader, raw-deflate and zstd chunks, zip reader) decodes it; `integrations/figma-scene.mjs` turns `nodeChanges` into REST-shaped nodes (absolute transforms, path blobs → SVG path data, instances expanded from their components with overrides). The canvas paste handler (`web/canvas-interactions.js`) hands Figma HTML to `window.figmaPaste` (`web/figma-panel.js`) and pastes the result like in-app layers (one undo step). Clipboard data contains image references only; missing bitmaps are reported.
- **File** `figmaFile({bytes,name})` / `figmaFileOpen()` (native picker) → `{document,warnings}`. A `.fig` file is a zip (`canvas.fig`, `meta.json`, `images/<sha1>`) or a bare `fig-kiwi` archive; embedded images are imported. Dropping a `.fig` on the canvas or Insert › Import Figma › Open .fig file… opens it as a new document. `.pen` files are refused: they are encrypted by their vendor and only readable with the vendor's tools, so Verynize does not attempt to decrypt them.

Conversion: pages, hierarchy, rotation/flip (from the node transform), opacity, blend modes, clip content, corner radii, solid/linear/radial/angular/diamond gradients (CSS geometry from the gradient handles; diamond approximated as radial), multi-paint stacks, image fills (fill/fit/stretch/tile → cover/contain/fill/none), strokes (uniform → outline with inside/centre/outside offset, dashed; per-side → border widths with child offsets and padding compensated), drop/inner shadows, layer/background blur, auto layout (direction, per-side padding, gap, wrap with counter-axis gap, alignment, hug/fill sizing, absolute children), constraints (left/right/centre/stretch/scale via the canvas `anchorPatch`), text (family, weight from style name, italic, size, alignment, line height, letter spacing, case, decoration, per-range bold/italic/colour/size) and vector/boolean/star/polygon/line geometry as embedded SVG images. Components and instances are flattened into named editable layers (`Instance (Component)`). Warnings name what is approximated: masks (kept hidden), per-range family/spacing/decoration, vertical text alignment, image crop transforms, text strokes, rotated parents, gradients inside multi-paint stacks that are off-centre. Fonts must exist locally for faithful text rendering.

**Figma account** (`desktop/figma-oauth.cjs`): `figmaOAuth.status/configure({clientId, clientSecret?, port?})/connect/cancel/disconnect`. Authorization code flow with PKCE (S256) and a random `state`; the code arrives on a loopback listener `http://127.0.0.1:<port>/figma/callback` (default 47615; the URI must be registered in the user's Figma OAuth app). Tokens and the optional client secret are sealed with Electron `safeStorage` in `userData/figma-oauth.json` (mode 0600; the client ID and port are plain). Access tokens are refreshed within a minute of expiry (single in-flight refresh). Without secure storage nothing secret is saved. The client ID is set in the Figma dialog (Insert › Import Figma, Settings › Connections › Figma). `VERYNIZE_FIGMA_OAUTH_ORIGIN` (loopback http only) points the endpoints at a local fixture server for tests. **Needs live credential:** no real Figma OAuth app was available; the flow is verified against a local fixture authorization server only.

Bounds: 20 MB document/API response, 200 MB `.fig` file, 5,000 converted layers (20,000 scene nodes), 100 pages, 80 hierarchy levels, 20 downloaded REST images (5 MB each, 15 MB total), 60 embedded `.fig` images (15 MB total). Requests time out after 30 seconds; sign-in after 5 minutes.

Tests: `node --test tests/figma-import.cjs tests/figma-binary.cjs tests/figma-oauth.cjs` (REST conversion and token routing; kiwi codec, archives, clipboard, `.fig`, fidelity of the converted scene; OAuth against a fixture server) and `node tests/figma-paste.cjs` (Electron: real clipboard paste, `.fig`/`.pen` drop, account settings). Binary fixtures are authored in `tests/fixtures/figma-scene-fixture.mjs` with an independently written schema using the field names the importer reads; no Figma file content is included. No authenticated remote request was made.

Sources: Context7 `/figma/rest-api-spec` endpoint, node and paint documentation; official [Figma file endpoints](https://developers.figma.com/docs/rest-api/file-endpoints/).

## Agent shell tools (dev server, running-app preview, terminal, editor actions)

Bridge-only MCP tools (`integrations/shell-tools.mjs`) let agents drive the user's running app. They are listed by the stdio server too, but answer "needs the Verynize desktop app" unless the call reaches the in-app bridge. `desktop/agent-shell.cjs` hosts them; `main.cjs` registers each window's open project with `registerShellWindow(win, {getProject})`.

- **Dev server** (`desktop/dev-server.cjs`, plain Node): one per project root. The command is, in order, the call's `command` argument, the per-project override saved in `userData/dev-servers.json` (`configure_dev_server`), or the package.json `dev`/`start`/`serve`/`preview` script run with the package manager from `packageManager` or the lockfile. Processes are spawned from argument arrays (never a shell) in the project root with stdin closed and their own process group. stdout/stderr go to a 512 KB ring buffer with ANSI codes stripped. The first localhost URL printed (0.0.0.0 becomes localhost) is probed until it answers, then opened in the preview pane. Stop, and app quit (`will-quit`), signal the whole group (SIGTERM, then SIGKILL).
- **Terminal**: `run_terminal_command {argv}` runs in the project root with a timeout (default 60 s, max 10 min) and returns the exit code and the last 30,000 characters. `background:true` returns an id; `read_terminal` reads the dev server (`"dev-server"`) or a job incrementally (`since`), lists terminals, or stops one. At most four background jobs run at once and 20 are retained.
- **Preview automation** (`desktop/preview.cjs` `previewAutomation(win)`): acts on the embedded `verynize-live-preview` iframe, re-checking for every call that it shows a localhost URL. Only fixed in-page functions run, with JSON arguments. `preview_snapshot` returns an outline (landmarks, headings, text, links and controls with CSS selectors) or the visible text, up to 60,000 characters; password values are never returned. `preview_screenshot` captures the pane (or one element) as a PNG of at most 1600 px width and 4 MB. Clicks and typing are trusted input events sent through the window's DevTools-protocol input domain, because `sendInputEvent` does not reach the out-of-process frame. If the debugger cannot attach, the tools fall back to synthetic DOM events and report `input:"synthetic"`. Console messages, navigations (with HTTP status) and load failures of the preview frame go to a 500-entry ring buffer. `capture_preview_to_canvas` reuses the live capture and inserts one artboard as one undo step.
- **execute_action** runs entries of the editor's command registry (`window.verynize.commands()/runCommand`) through `web/agent-bridge.js`. Short element ids select the targets first. OS clipboard commands are not exposed.

**Access and approval.** Tools fall into three classes: read (status, snapshot, screenshot, console, terminal output, action list), interact (preview open/click/type/scroll, capture, execute_action, stopping processes) and exec (`start_dev_server`, `configure_dev_server`, `run_terminal_command`).
- A bridge request may send `x-verynize-access: readonly|ask|edit|auto|full`.
  - `readonly` allows read tools only.
  - `auto` and `full` run exec tools without asking.
  - `ask`, `edit` or no header shows a native approval dialog for each exec call. The dialog offers "allow this project until quit".
- `setBridgeOptions({shellExec:false})` or `VERYNIZE_SHELL_EXEC=0` refuses every exec tool. `confirmExec` replaces the dialog (embedders and tests).

Tests: `node --test tests/dev-server.cjs` (real child processes and a Node http fixture project started through `npm run dev`) and `node tests/mcp-shell.cjs` (Electron plus a real MCP client against the bridge).

## Integrated terminal (code mode)

`desktop/terminal.cjs` (registered per window in `main.cjs`) runs interactive PTY shells with `node-pty` for `web/src/islands/code/terminal-panel.tsx`.

- `terminalCreate({cwd,cols?,rows?})` → `{id,shell,cwd}` starts the user's login shell (`$SHELL -l`, else `/bin/zsh`) with `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=Verynize` and no `ELECTRON_*` variables. `terminalWrite({id,data})` (text of at most 64 KB; the panel splits pastes), `terminalResize({id,cols,rows})` (2–1000 × 1–500) and `terminalKill({id})` (SIGHUP to the shell's process group, SIGKILL after 1.5 s).
- `onTerminalData(cb)` receives `{id,data}` batched every 8 ms in pieces of at most 64 KB; `onTerminalExit(cb)` receives `{id,exitCode,signal}` once, after the last data. Both return an unsubscribe function.
- `cwd` must be an existing absolute directory (realpath-compared): the open project or a folder inside it, one of its `git worktree list` entries, or a folder under `~/Verynize/workspaces/`. The repository registry can replace that policy with `require('./terminal.cjs').setTerminalCwdValidator((realCwd, {projectRoot, defaultAllowed, win}) => boolean)`; its answer is final (return `defaultAllowed` to fall back), `null` removes it.
- At most eight terminals per window. Closing the window kills its terminals; `will-quit` and process exit kill all of them (SIGHUP, 300 ms grace, SIGKILL).

`node tests/code-terminal.cjs` covers the API against real PTYs (guard, limits, cap, cleanup on quit, no orphan processes) and renders the panel component from a temporary test bundle.

## Named accounts, Verynize tools, chat autonomy, global search and workspace moves

- `onboardingState()` → `{skip}`: the first-run onboarding (account, then agents) is skipped when `VERYNIZE_SKIP_ONBOARDING=1`, which every Electron test sets. Completion itself is remembered by the renderer (`localStorage` key `verynize.onboarding`).
- `agentProfiles.{list,add,rename,remove,setDefault,setChat,chat}` (`desktop/agent-profiles.cjs`): named Claude Code / Codex accounts. Each has a private 0700 folder `userData/agent-profiles/<agent>/<id>` passed as `CLAUDE_CONFIG_DIR` / `CODEX_HOME`; `system` is the computer's own login. `agentAccountStatus`, `startAgentLogin`, `agentLogout` and `agentUsage.read` accept `{profile}`. Credentials are never read beyond display claims.
- `agentToolConfig.{list,saveServer,setEnabled,removeServer,setPermission}` (`desktop/agent-tool-config.cjs`): MCP servers and per-tool allow/ask/deny defaults that Verynize passes to every run (global or one project; Claude, Codex or both). Environment values are write-only (the renderer sees names only); Codex gets them through `env_vars`, never argv.
- `agentAutonomy.{get,set}` (`desktop/agent-autonomy.cjs`): per-chat allowed/denied tools, auto-approve rules, max turns, budget and plan-before-edits, enforced in `agent-runtime.cjs` (events `autonomy` and `policy`).
- `projectSearch.{search,open}` (`desktop/project-search.cjs`): ripgrep (bundled `@vscode/ripgrep` when installed, else `rg` on PATH) or a Node walker over every registered project, honouring .gitignore, plus `*.verynize.json` page/layer/text matches.
- `repositoryMoves.{moveInside,relocate,moveAcross,chooseDestination}` (`desktop/repository-moves.cjs`): committed `git mv`, folder rename/move with `git worktree repair`, and cross-repository moves with history (`format-patch`/`am` or `subtree`). Clean trees only; refused while an agent runs there.
