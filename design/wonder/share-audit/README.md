# Share parity: Verynize vs Wonder (2026-11-02)

Gap analysis and fix record for **Share**: the Share button at the top right of a file, the Share popover, invitations, file
visibility, Copy link, opening a shared link (desktop, Chrome, Safari), and collaboration between accounts. The checklist is
[CHECKLIST.md](CHECKLIST.md), and the implementation contract the three workstreams followed is [CONTRACT.md](CONTRACT.md).

> **Evidence is not published.** The screenshots, pairs (`pairs/`, `pairs-after/`) and JSON sidecars contain personal account data, so this public repository keeps only the notes and scripts (see `.gitignore`). Regenerate the Verynize side with `npm run build:ui && node design/wonder/share-audit/verynize/capture-after.cjs`, then `python3 design/wonder/share-audit/make-pairs.py`. Links to images below resolve only in a local checkout that has them. Personal emails and Wonder identifiers in the notes are replaced by placeholders.

  - Rebuild both with `python3 design/wonder/share-audit/make-pairs.py`.
  - Re-capture the after side with `npm run build:ui && node design/wonder/share-audit/verynize/capture-after.cjs`.
- **End-to-end tests** (no stubbed server answers): `tests/share-collab.mjs` (desktop, three accounts: Share popover invite as Editor →
  copied link → invitation → Maybe later → Join → co-editing both ways; Viewer invite → Decline → no access → new invite → Join →
  read-only; removal from the workspace while connected), `tests/web-cloudflare.mjs` (an invited signed-in non-member in Chromium and
  WebKit, dev and production builds: invitation → Join → Editor), `tests/share-popover.cjs`, `tests/cloud-share.mjs`.
- **Fixture differences, not gaps.**
  - Verynize's Sunbird is a reconstruction (white frames on #2b2b2b, one rotated, a few "H"); Wonder's has more layers and shaders.
  - Accounts have no photo, so avatars are initials where Wonder shows portraits; the workspace is "Adam Owner's workspace".
  - Wonder's web captures include the browser's toolbar, so its page area is smaller; Verynize's are the page viewport.
  - Safari is Playwright WebKit (Safari's engine), not the Safari app. Wonder's Safari evidence is the real app.
  - Wonder shows a profile-switcher rail and a top bookmarks bar from the real browser; Verynize's web build keeps the desktop's tab
    strip.
- **Deliberate differences** (the product decision in CONTRACT.md):
  - **All roles are free.** Viewer, Editor and Admin are offered without "Pro" badges or "Add admins and editors with Pro. Viewers are
    free. View Pro". There is no plan, billing or Upgrade dialog.
  - **The web works in every browser, Safari included, with no forced desktop handoff.** A link opens the file in the browser
    directly; there is no "Opening in the desktop app…" page, no "This browser isn't supported" page.
  - **Two or more editors collaborate.** Wonder Free collaborates owner → Viewers only.

## Per id

Verdicts: **Match** means strings, order, layout, size and colours agree within the capture tolerance (Wonder's raster estimates are
±2 CSS px). **Close** means it agrees apart from the listed details. **Deliberate difference** is a product choice above. **Not
observable in Wonder** means Wonder's evidence does not show the behaviour.

## Fixes made in this pass

- **Email field** rings red for "Enter an email address to invite." as well as for invalid chips (`share/share-popover.tsx`).
- **Share button** padding 8 px: 49.25 px wide, Wonder 49 (`share/share-popover.tsx`).
- **Members row menus**: icons, and Remove from workspace / Cancel invitation in the destructive colour; the Remove member and Cancel
  invitation confirmations use the red action of the Share visibility dialog (`settings/members.tsx`).
- **Tests**: `tests/share-collab.mjs` no longer stubs the invitation answer (the whole flow runs against workerd);
  `tests/web-cloudflare.mjs` covers an invited signed-in non-member in Chromium and WebKit. Three suites that broke with the Share work
  were updated (see the commit "test: update three tests for the Share work"): none was a product defect.

The real invitation flow (invite from the popover, the in-app invitation, Maybe later, Decline, Join with Editor and Viewer, workspace
removal while connected) worked on the first end-to-end run; no server or client defect turned up in it.

## Remaining gaps

- **Viewer chrome (SC3).** Verynize shows the Share button and an inert inspector to Viewers; Wonder hides both.
- **Invitation card (SC4).** Workspace name instead of its slug.
- **Members page (SI5, SC4).** Overview cards and the Room access section differ; the confirmation footer has no darker band; row menu
  text is 12 px.
- **Sign-in page (SL2).** No social sign-in and no artwork.
- **App menu (SL4).** Flat list; no Rename / Move to trash in it.
- **Multiplayer tools (SC1).** Anchored 67 px further right.
- **Not verified:** real email delivery, the real Safari app (WebKit only), production.
