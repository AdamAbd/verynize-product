# Verynize follow-up capture (2026-10-31)

This is the Verynize half of the follow-up to [README §8](../README.md#8-status-after-fixes-2026-10-31). It covers the D1/D2 frame tool, the G1–G6 "Top remaining gaps" and the H1–H9 "Assumptions" items. The Wonder half is in [../wonder/notes-2026-10-31.md](../wonder/notes-2026-10-31.md); its file ids are the ones reused here.

This pass changed documentation and captures only. No file in `web/`, `desktop/` or `integrations/` was edited.

## Method

- **Build and capture.** `npm run build:ui`, then:

  ```sh
  node design/wonder/properties-audit/verynize/capture.cjs --new-only D1 D2 G1 G2 G3 G4 G5 G6 H1 H2 H3 H4 H5 H6 H7 H8 H9
  ```

  The setup is the same as before: real Electron through Playwright `_electron`, content 1440×870, `--force-device-scale-factor=2`, `--force-color-profile=srgb`, a temp `--user-data-dir` and `VERYNIZE_SKIP_ONBOARDING=1`.
- **New in `capture.cjs`.**
  - `--new-only` skips any PNG that already exists.
  - A `shoot()` helper takes window, canvas, canvas+panel and single-element crops.
  - A follow-up block holds the D/G/H ids. When only those ids are requested, the older A–C blocks are skipped (labelled block `legacy:`).
- **Output.** 93 new PNGs, each with an entry in `metrics.json`. The entry records the node list, selection, tool, open menus and per-shot extras.
- **Pairs.** `python3 design/wonder/properties-audit/make-pairs.py` ran cleanly: 185 pairs, up from 110. That is 75 new; existing pairs are byte-identical.
- **Crop sizes.**
  - Panel shots are `aside#properties` (562 px wide, plus any open popover).
  - `D1-*-created` are the full window (2880×1740, the same as Wonder's).
  - `D2-corner-zoom` is `#canvas-wrap`.
  - `H8-*` is the canvas plus the panel.
  - `G4-*` and `H9-*` are the alignment matrix only (216×112, the same as Wonder's crops).
- **Naming.** Ids and state names copy the Wonder files where they exist.
  - H2, H3 and H5 had no Wonder files yet, so their names are mine (`H2-selection-colors`, `H2-target-clicked`, `H3-mixed`, `H3-replaced`, `H5-constraint-menu`, `H5-scale-existing`).
  - Verynize-only extras: `D1-frame-tool-window`, `D1-frame-presets`, `D1-toolbar-click-created`, `D2-toolbar-click`, `G5-*-preview`, `G6-gradient-editor`, `G6-shadow-bound-editor`, `H1-after-click`.
- **Wonder crop caveat.** Wonder's plain `G4-column-*.png`, `H9-active-only.png` and `H9-hover-active.png` do not show the matrix; they caught the gap fields. Its `*-verified.png` retakes are correct. Verynize therefore saves both names, and only the `-verified` pairs should be read.
- **Tooltips.** Verynize icon buttons use a native `title` (`IconButton`, `web/src/islands/inspector/controls.tsx:52-56`). The OS draws it, so it never appears in a screenshot. The title text is recorded in `metrics.json` instead. Wonder draws its own tooltips (H1, H6, H7, H9).

## D1. Frame tool with nothing selected

**Evidence**
- [D1-collapsed](D1-collapsed.png): F pressed. [pair](../pairs/D1-collapsed.png)
- [D1-frame-tool-window](D1-frame-tool-window.png) and [D1-frame-presets](D1-frame-presets.png): the floating preset list.
- [D1-click-created](D1-click-created.png) [pair](../pairs/D1-click-created.png), [D1-drag-created](D1-drag-created.png) [pair](../pairs/D1-drag-created.png), [D1-preset-created](D1-preset-created.png) [pair](../pairs/D1-preset-created.png).
- [D1-toolbar-click-created](D1-toolbar-click-created.png): the toolbar button.

**What Verynize does now.** There are two separate paths.

1. **Toolbar Frame button (the user report).** Clicking it does not arm a tool. It inserts a frame at once:
   - "Frame", 500×360 at x 120, y 150;
   - `#ffffff`, radius 12, Clip content on;
   - selected immediately.

   The tool stays `move`. If a frame is selected, the new frame is nested inside it. The chain is:
   - `web/src/islands/chrome/CanvasOverlays.tsx:71` defines `{ id: "add-frame", tool: "frame" }`.
   - `:136` `onClick={() => run(id)}`.
   - `web/src/islands/chrome/legacy.ts:63-67` `run()` clicks the parked legacy `#add-frame`.
   - `web/app.js:29` `$('#add-frame').onclick=()=>add('frame')`.
   - `web/app.js:22` `add()`: `w:type==='frame'?500:250`, `h:…frame?360`, `color:…frame?'#ffffff'`, `{clipContent:true}`, `parent=chosen()?.type==='frame'?chosen():null`, `selection=new Set([n.id])`.
2. **Keyboard F (the real tool).** The tool is armed and nothing is created.
   - `web/canvas-interactions.js:1384` `tool.frame` runs `setTool('frame')`.
   - `:361-368` `setTool` unhides `#frame-presets`.
   - **Properties does not change.** It still shows the Page section (`web/src/islands/inspector/properties.tsx:1027`, `{!node ? <PageSection …/> : null}`), and no inspector code reads the tool.
   - The presets are a separate floating popover above the toolbar: 260 px wide, `max-height:min(420px,48vh)`, scrolling (`web/canvas.css:63-69`). It is built in `web/canvas-interactions.js:1516-1529` with the hint "Drag on the canvas to draw a frame, or choose a size".
   - **Click** on the canvas creates a **400×300** frame at the click point (`web/canvas-interactions.js:981`, `{frame: [400, 300], …}`). Wonder creates 100×100.
   - **Drag** creates a frame of the dragged size in document units: 322×242 at 80 % zoom (`startDraw`, `:968-993`). This matches Wonder.
   - **Preset** "iPhone 17" creates a 402×874 frame named "iPhone 17", selects it and zooms to it (`:1525`). This matches Wonder.
   - After a draw or a preset, the tool returns to Move. This matches Wonder.

**Preset data.**
- `FRAME_PRESETS` exists at `web/canvas-interactions.js:14-19` and is exported as `window.BetterCanvas.FRAME_PRESETS` (`:1621`).
- It has 4 groups and 13 presets:
  - **Smartphone:** iPhone 17, 18 Pro, Air, 18 Pro Max.
  - **Tablet:** iPad Air 11", iPad Mini 8.3".
  - **Desktop:** MacBook Air, MacBook Pro 14"/16", Desktop, TV.
  - **Presentation:** Slide 16:9, 4:3.
- Every value that exists matches Wonder.
- Wonder differs in four ways:
  - Its groups are called **Phone, Tablet, Desktop, Presentation, Smartwatch, Paper, Social media**.
  - Phone adds iPhone Duo Folded 466×678 and iPhone Duo Open 626×890.
  - Smartwatch (2), Paper (3) and Social media (6) are missing in Verynize. Wonder's notes list their values.
  - Wonder's list sits **in Properties**: a "Frame" heading, then 7 collapsible category rows (chevron x 24, icon, label x 56, pitch 30). It has no Page section and no floating popover.
- No other preset data exists. `integrations/` has none, and the only test use is `tests/canvas-interactions.cjs:89,102`.

**Fix for 1:1 parity (sketch)**
1. **Toolbar button arms the tool.** In `wireToolbar` (`web/canvas-interactions.js:1507-1513`), rebind `#add-frame.onclick` to `setTool(tool === 'frame' ? 'move' : 'frame')`, as is already done for select, pan and scale. Keep immediate insertion available as a command or menu item ("Insert frame"). The island toolbar's `aria-pressed` already follows `#workspace[data-tool]` (`web/src/islands/chrome/hooks.ts:32`).
2. **Properties shows the presets.** Move `useTool` (or an equivalent `useObserved` on `#workspace[data-tool]`) into a shared lib. In `properties.tsx` around `:1027`, render a new `FramePresetsSection` instead of `PageSection` when `tool === 'frame'` and nothing is selected. That section should have:
   - an `h3` "Frame";
   - one Radix `Collapsible` per category, all collapsed by default, with lucide icons (Smartphone, Tablet, Laptop, Presentation, Watch, File, MessageSquare);
   - rows with the name on the left and `W × H` right-aligned at x 256;
   - `data-preset` kept on each row.

   A row should run the existing preset action. Expose it as `window.design.insertFramePreset(name)` or click the legacy `[data-preset]` button. Then remove the floating `#frame-presets` popover (`web/canvas.css:63-69`, `web/canvas-interactions.js:1516-1529`, and the `presets.hidden` line `:367`).
3. **Data.** Rename Smartphone to Phone. Add the two iPhone Duo sizes and the Smartwatch, Paper and Social media groups from Wonder's notes.
4. **Click size.** Change `web/canvas-interactions.js:981` from `frame: [400, 300]` to `[100, 100]`.
5. **Tests that change.**
   - `tests/canvas-interactions.cjs:89`: `#frame-presets` visibility moves to the inspector list. `:102`: the preset click.
   - `tests/canvas-page.cjs:12` and `tests/canvas-advanced.cjs:2` click `#add-frame` and expect a frame immediately. They should press F and click the canvas instead, or use the new insert command.

## D2. New frames are rounded

**Evidence**
- [D2-click](D2-click.png) [pair](../pairs/D2-click.png), [D2-drag](D2-drag.png) [pair](../pairs/D2-drag.png), [D2-preset](D2-preset.png) [pair](../pairs/D2-preset.png), [D2-toolbar-click](D2-toolbar-click.png).
- [D2-corner-zoom](D2-corner-zoom.png) [pair](../pairs/D2-corner-zoom.png): Shift+2, then deselect, at 248 %.

**What Verynize does now.** All four creation paths give the same result:
- Opacity 100, **Corner radius 12**, Clip content on, Background Fill `FFFFFF` 100 %.
- On the canvas: `border-radius: 12px`, `overflow: hidden`, `rgb(255,255,255)`. The corner is visibly round.

Wonder gives radius **0**; everything else is the same.

**Source**
- `web/app.js:3`: `const defaults={… radius:12 …}`. This applies to every type created through `add()`: frame, rectangle, text and shader.
- `web/app.js:22`: `add()` spreads `defaults` and then sets the frame overrides `color:'#ffffff'` and `clipContent:true`. It never overrides `radius`.
- Every renderer path goes through `add()`: the toolbar (`app.js:29`), click/drag (`canvas-interactions.js:991`, `ed.add(kind, extra)`) and presets (`:1525`).
- Rendering: `web/node-style.js:666` (`border-radius`) and `:679` (`overflow:hidden` when `clipContent`).
- **The headless side has no rounded default.**
  - `integrations/jsx-codec.mjs:18-22`: `NODE_DEFAULTS` has `radius: 0` and `clipContent: false`.
  - `integrations/design-edit.mjs:363,366`: JSX-created frames get `color: 'transparent'`. This is Tailwind semantics, so it is intentionally not the same as the canvas tool.
  - `integrations/design-store.mjs:141`: `create_node` has `radius: 0`.

**Tests that assert these defaults**
- **None assert radius 12 on a new frame.** I searched every `tests/*`, `integrations/*.test.mjs` and `eval/**/*.mjs`. Every `radius: 12` hit is a fixture value or a CSS import (`integrations/codec-html.test.mjs:383,389`), not a creation default.
- `tests/canvas-interactions.cjs:94` asserts that a drawn frame has `clipContent === true`. This stays true.
- `tests/canvas-interactions.cjs:92` asserts the drawn size. `:103` asserts the preset name and size (402×874).
- `tests/canvas-page.cjs:12` and `tests/canvas-advanced.cjs:2` depend on `#add-frame` inserting at once (see D1). They do not depend on the radius.
- `tests/capture-fidelity.cjs:2` asserts `clipContent` on captured web pages. This is unrelated.

**Fix (sketch).** In `web/app.js:22`, change `...(type==='frame'?{clipContent:true}:{})` to `{clipContent:true, radius:0}`. Then decide separately whether rectangles should also default to 0; Wonder's rectangle default was not captured. Add a regression assert in `tests/canvas-interactions.cjs` §2 that drawn, clicked and preset frames have `radius === 0`. Nothing needs to change in `integrations/`.
