# File/page switching, loading visuals, and collaboration-safe caching audit

Date: 2026-11-06. Read-only source audit; only this report was written. Read `CLAUDE.md` and `web/src/islands/README.md` first. References are repository-relative, with current source line numbers (several legacy functions occupy one line). Pen/Figma appearances below are the requested reference behavior, not independently verified product observations.

## Findings that change the implementation plan

1. File library implementation is **`web/wonder-shell.js`**, not `web/app.js`. Local documents already reside in memory and localStorage. IndexedDB stores cloud outboxes and recovery backups, not a separate local-file read path.
2. Canvas rendering is already incremental: `web/canvas-render.js:2`, `:305`. It keeps node elements/memos, patches changed nodes, and culls offscreen boards. Switching pages still discards elements absent from the next page (`:342`); the rest of `app.js` still rebuilds legacy panels and serializes/clones documents.
3. `document-will-change` is a **disconnect boundary**, not an early loading signal: it fires after outgoing upload/flush work (`web/document-lifecycle.js:6`). Reusing it as the sole loading trigger misses potentially most of the wait.
4. `pageLoader.render()` runs **after** canvas rendering (`web/app.js:22`). CSS blur alone on today's overlay would blur an empty target stub, not preserve the outgoing page.
5. Native file tabs reopen a library copy; they do **not** re-read or reattach the original native path. A cache must not claim native freshness without addressing this.
6. Inactive cloud rooms have no live subscription. Loaded inactive pages of the **active** room do receive operations. Treat these two cases separately.

## Switching paths and current visible behavior

### File tabs and other file entry points

| Entry | Execution/awaits | What is visible today |
| --- | --- | --- |
| Title bar tab | `TitleBar.tsx:99` → `openFileTab()` (`chrome/file-tabs.ts:94`) → `fileLibrary.open(id)`. Same current id only shows editor; failures are console-logged. | Existing document remains visible during waits; no dedicated tab loading overlay or spinner. Active-tab identity changes with library state, not at click. |
| Close active / close others | `file-tabs.ts:107` chooses right, then left neighbor; last tab shows Files. `:124` opens retained tab when necessary. | Same loader; closing current tab can hide its tab before replacement finishes. |
| File switcher | `FileSwitcher.tsx:128` chooses `openFileTab`; new-file row at `:93` is creation, preview row at `:109` is a different preview-tab system. | Palette closes, outgoing editor remains until load. Do not cover preview switches with document-loading logic. |
| Files home / API / imports | Library cards invoke `openFile` (`wonder-shell.js:87`); API exported at `:97`; JSON import `app.js:50`, Figma `figma-panel.js:51`, agent open `agent-bridge.js:138` route through library/lifecycle. | Same underlying document replacement; hook the core path, not just title-bar clicks. |

**Local library open** (`web/wonder-shell.js:29–54`, `:95–106`): initial library is parsed from `verynize-library-v1` localStorage. `openFile` finds an in-memory record, checks account visibility and document validity, awaits serialized `documentLifecycle.prepareSwitch(options)`, checks optional cancellation, sets library active id, runs `documentSafety.withSource(...setDocument(file.document))`, persists, shows editor, emits `library-file-opened`. There is no per-tab IndexedDB/disk read. Detached cloud records use this local path too.

`setDocument` aliases `loadDocument` (`web/app.js:86`): validate/repair with documentSafety, checkpoint outgoing design, replace document, clear selection, synchronously render. Rendering (`:22`) traverses nodes, measures sizing via layout reads, rebuilds legacy layers/tokens/inspector controls, updates canvas interaction chrome, invokes pageLoader, schedules save, and notifies subscribers (cloning for callbacks that accept arguments). `wonder-shell.js:46` serializes/clones/persists changed library documents; `:38` serializes library storage. `app.js:13` separately schedules anonymous document persistence at idle, timeout 200 ms. These CPU/storage costs can block painting even when storage lookup is instant. Validation failure retains the old document and reports recovery information; no loading cleanup mechanism exists yet.

**Lifecycle cost** (`web/document-lifecycle.js:2–11`): promise chain serializes preparation, not the entire open transaction. Unless cloudJoinEpoch is present, signed-in current file storage is awaited, then cloud flush; event dispatch disconnects room listeners; native detach IPC follows unless preserveNative. Local opens lack the cloud joinRequest guard by default: add one coordinator token across file sources rather than relying on this queue to enforce latest-click wins.

**Native JSON open** (`web/desktop-panel.js:278`, `web/wonder-shell.js:97`): native dialog/IPC → `DesignFiles.open()` target resolution, document read/validation/revision → watch selected file → library `openNative`, clone/update by nativePath, possibly await account room creation, then `openFile(...preserveNative:true)`. `desktop/design-files.cjs:14–17` installs one fs.watch, debounces 80 ms, reads and checks revision; `web/desktop-panel.js:282` offers confirmation before replacing externally edited document. Save is revision checked (`desktop/design-files.cjs:19–24`). Switching away detaches this watch. Clicking a native tab later takes ordinary local open and detaches again: no path-based reopen call here, no disk freshness check. Distinguish this existing gap from a proposed cache regression. Native dialogs can cancel without a switch; only begin visual loading once a file was selected, or give dialog waiting its own cancelable phase.

**Cloud-backed tab** (`web/wonder-shell.js:52`, `web/cloud-panel.js:929–1089`):

1. `openRoom/connect`: increment joinRequest; await outgoing flush, validate room/token/session, retain old room connection while fetching next room.
2. In parallel read IndexedDB outbox and GET room (`?lazy=1` for ordinary joins), but **await both before displaying either** (`:953`). Thus persisted cache is currently offline recovery, not immediate SWR. Failed network can restore an existing outbox; HTTP access failures detach/report instead (`:964–980`).
3. Flush outgoing edits again after fetch (edits may have occurred during fetch), then disconnect (`:983`). `flushBeforeSwitch` waits up to 15 s for image uploads, calls ensureAll for deferred page operations (30 s waiter timeout), then flushes. `flushOps` waits up to 5 s for WebSocket acknowledgements, then POSTs remaining batches (`:619–654`). Those are code timeout bounds, **not measured switch durations**.
4. Open existing library record using cloudJoinEpoch/isCurrent, or create a record from fresh document. Existing library content may render before reconciliation. Set connection, confirmed state, pending batches, lazy-page source, role, and revision; apply initial document when required. Restore pending/deferred operations and diff genuine offline changes (`:1034–1083`).
5. Start socket, emit room change, return. This completion is **not** proof that fresh socket snapshot has arrived. `welcome` → `sync` with loaded page ids/revision; snapshot replaces confirmed state or responds `same`, prunes acknowledged batches and replays remaining pending edits (`:842–895`).

Possible visual sequence inferred from code: outgoing page during HTTP/flush → cached library page or remoteOnly empty placeholder → fresh/rebased state. Whether each intermediate frame paints depends on awaits and task scheduling; no screenshot/timing measurement was performed. Startup reconnect (`:1099–1107`) and direct invite open also enter connect; cover both.

### Page switching

Sidebar `PagesSection.tsx:91` calls `design.setActivePage`; double-click rename and delete helper also activate a page (`:24`, `:94`). Public `setActivePage` and `setView` (`web/app.js:86`) synchronously update activePage, clear selection, and render. Legacy `#pages` onchange, add-page and delete-page mutate activePage directly (`:34`). Saved views (`web/views-templates.js:83`) and agent focus (`web/agent-bridge.js:119`, `:160`) use setView. Whole-document replacement/undo can also change activePage. A pre-render identity comparison covers these paths better than wrapping sidebar handlers alone.

For loaded local/cloud pages there is no data await: render happens immediately, and CPU/layout cost is the latency. For unloaded cloud pages the selected page is an empty nodes stub; the old canvas elements are removed, then `pageLoader.render()` requests page ids (`web/page-loader.js:125`). `#page-loading` covers all workspace with opaque `--shell-canvas` and text, cursor progress (`page-loader.css:3–17`); no Gaussian blur or preserved outgoing content. Offline text says the page loads when reachable. Ordinary page selection does not await `ensure()`; its 30 s rejection only applies to explicit callers. A disconnected unloaded page can remain in loading state indefinitely.

Socket `pages` message fills confirmed page/undo history, releases deferred local operations, rebuilds document (`web/cloud-panel.js:584–611`). Already-loaded repeated responses are ignored. Missing ids settle page-loader state. `received()` settles/hides overlay **before** rebuild, so new ready signaling must occur after render, not merely on received. Concurrent page selections should only dismiss their own matching loading generation.

## Existing caches and collaboration guarantees

| Mechanism | Existing behavior / limitation |
| --- | --- |
| In-memory library | All file records/documents retained, `lastSerialized` map suppresses duplicate writes (`wonder-shell.js:29–46`). No bounded document LRU. `summaries()` avoids cloning documents (`:98`); `list()` clones/validates them (`:97`). Account-backed persisted records deliberately use remoteOnly stubs (`:38`). |
| Active document | Full loaded pages remain in design; switching back is data-cache hit, but outgoing DOM is discarded. No page eviction. |
| Lazy prefetch | `page-loader.js:76–95`: 1500 ms default delay then idle callback (2 s timeout), smallest pages first; requests **all** missing ids. `verynize.pages.prefetch=off` disables. `wanted` deduplicates; reconnect resumes (`:234`); no byte budget/LRU/concurrency policy. |
| Cloud outbox | `cloud-panel.js:658–732`: IndexedDB `verynize-cloud/outbox`, server|room key, confirmed document/revision, client id/batch counter, pending, unloaded/deferred state; writes debounce 150 ms. Limits 4000 ops / 1.5M serialized characters; overflow retains confirmed and uses file diff fallback. Not a bounded general render cache. |
| Incremental elements | `canvas-render.js:91`, `:305–351`: maps of elements/memos, dirty tracking and shader lifetimes; only active page survives. Token changes dirty nodes. Culling conservatively hides offscreen clipping frames; flags allow full rebuild/culling off. |
| Experimental tiles | `canvas-tiles.js:1–16`: opt-in only (`verynize.canvasTiles=1`); 512 px tiles, 96 tile limit, four-tile drawing budget, low zoom threshold .25. Page/token changes clear cache (`:64`); damage tracks old/new bounds and order (`:130–135`); image cache max 64 (`:154`); resize/fonts invalidate (`:423`). This is an overview renderer, not full-fidelity page switching. Nominal tile RGBA storage ~97.5 MiB before images/overhead. |

Loaded inactive pages receive `receiveOps` just like active pages (`cloud-panel.js:562`). Unloaded node ops are filtered (`page-loader.js:155`) because a subsequent page response on the **same ordered socket** includes preceding changes; later operations then apply to loaded data. Page removal/root operations adjust unloaded state. Local unloaded edits wait in deferred, including removal so undo can restore content (`:173–215`).

Room switch disconnects socket, clears confirmed/pending/pageLoader state (`cloud-panel.js:749–780`). Inactive-room library documents are therefore stale until rejoined. Server lazy snapshots/page reads include revision (`cloud/rooms.js:91–120`); socket sync uses exact revision equality for `same` and returns ack watermark (`:862–890`). Server handles stamps/duplicate batches (`:286–368`); legacy snapshot writes require baseRevision (`:258–279`). `web/cloud-ops.js:280–295` explicitly distinguishes authoritative stamp-store application from client application: **do not replay arbitrary old remote ops and assume client Ops.apply performs LWW protection**. Preserve server ordering or request a fresh snapshot.

## Proposed design and division of ownership

### Shared contract (agree before parallel work)

Track B owns a new standalone `web/switch-coordinator.js`, loaded before app.js. It exposes a presentation-neutral state/event protocol; Track A can build against a fixture producer without editing B's files.

- `begin({kind:'file'|'page', from:{fileKey,pageId}, to:{fileKey,pageId}, reason}) -> token` before flushing, fetching, or destructive render.
- `phase(token, 'preparing'|'fetching'|'cached'|'rendering'|'revalidating')`.
- `rendered(token,{fileKey,pageId,contentVersion, freshness:'confirmed'|'provisional'})` only after target DOM/layout and relevant canvas overlays are committed.
- `finish(token)` / `fail(token,error)` / `cancel(token)`; only current token can clear busy state. Identity checks prevent an old callback revealing the wrong canvas.
- Synchronous `subscribe` plus `switch-loading-change` event, `getState()`, and a pre-render callback (`beforeCanvasCommit`) for A to preserve outgoing appearance. `document-will-change` keeps its existing disconnect semantics; do not fire it at begin.
- No network, authoritative model edits, or pending-op ownership in A. Cached/provisional is distinct from fresh/interactive. Do not clear a pending file overlay because an inner page-loader emitted idle.

**Track A — loading visuals**, owns NEW `web/src/islands/chrome/SwitchLoading.tsx`, NEW `web/src/islands/chrome/switch-loading.css`, NEW `web/src/islands/chrome/switch-loading-visual.ts`, NEW `tests/switch-loading-visuals.cjs`; minimal edit to `chrome.tsx` to mount/import, and `web/page-loader.css` to integrate the existing status node. Only own chrome token block in globals.css if needed. No changes to cloud-panel/app/wonder-shell.

File phase: opaque token-colored blank surface covering canvas workspace, centered LogoIcon, visually no text/spinner, accessible status label. Tabs/sidebar remain visible. Cover/hide grids, canvas tools, selection handles, presence, tiles and preview-frame overlays inside the workspace so only logo is visible there; preserve their DOM/ids. Use canvas theme background, not target document background. Block canvas editing/keyboard actions while target is uncommitted, but keep tabs usable to supersede the request. Restore interaction and old content on failure.

Page phase: capture outgoing visual **before** render mutates its DOM, show a clipped noninteractive presentation surface with strong blur (initial 16 CSS px, tune visually) over the canvas area while target renders underneath. Never blur title/sidebar. Do not simply clone live shader/WebGL canvases or iframes and expect a faithful image. Prefer retaining the live outgoing render surface through B's renderer handoff; a visual snapshot fallback must copy bitmap canvases, remove duplicate ids/data selectors, disable embedded previews/scripts and explicitly handle unsupported content. No interactive stale DOM. Keep `#page-loading` as the unique status/accessibility hook with offline wording; replace its opaque visual treatment while blur is active. A supplies presentation capture/release; B owns safe renderer state movement.

For real waits, ensure the overlay has an opportunity to paint **before** synchronous heavy work (a scheduled task after a frame, not merely await Promise.resolve). Avoid forcing artificial multi-frame delays on instant hits. A ready result may skip visible loading if no wait reaches a paint; measure that tradeoff. Respect reduced motion; no spinner/minimum-duration delay required. Release only after matching rendered event and next paint opportunity. Clean up on error, supersession, missing/deleted page, sign-out and home navigation.

**Track B — caching and switching**, owns NEW `web/switch-coordinator.js`, NEW `web/switch-cache.js`, NEW `web/page-render-cache.js`, NEW `tests/switch-cache.cjs`, NEW `tests/cloud-switch-cache.mjs`; narrow integration edits to `web/wonder-shell.js`, `web/app.js`, `web/document-lifecycle.js`, `web/cloud-panel.js`, `web/page-loader.js`, `web/canvas-render.js`, optionally `web/canvas-tiles.js`. Own native reopen changes if implemented: `desktop/design-files.cjs`, preload + typed bridge/platform contracts, `web/desktop-panel.js`. Keep most logic in new modules, not additional long inline functions.

Exact hook sites: openFile entrance/finally (`wonder-shell.js:52–54`); connect entrance + post-rebuild/socket snapshot (`cloud-panel.js:929`, `:871`); before canvasRender.render and after canvasApi.afterRender (`app.js:22`); page identity transition fallback covers direct mutations at `app.js:34`/`:86`; pageLoader attach/reset/received/missing (`page-loader.js:136`, `:190`, `:199`, `:218`); accepted ops/snapshot/page messages (`cloud-panel.js:562`, `:587`, `:871`); renderer detach/restore around `canvas-render.js:305` before unseen-node disposal. Nested cloud library opens inherit file token, not start competing switches.

**Integrator-only shared files:** `web/index.html:7` script order (coordinator before app; cache after dependencies), hosted-web legacy script loading manifest (locate matching entries before integration), `scripts/test-manifest.mjs` registrations/source globs, any shared bridge type declarations. Neither parallel track independently edits these; integrator applies combined changes once. No generated web/dist edits. Independent commits/worktrees therefore overlap only by an explicit integration patch, not by simultaneous app.js modifications.

### Cache data and invalidation

Suggested starting budgets are design choices to benchmark, not existing limits: 64 MiB serialized document/page cache, max 8 inactive files; 32 MiB estimated render resources / 3 inactive pages; separate accounting for bitmaps, DOM, decoded images. Pin active state and any unsaved/pending/deferred work; cache eviction must never delete the durable outbox or an authoritative local file.

Key documents by `{source, account/session namespace, normalized server+roomId | stable libraryId | canonical nativePath}`. Never key solely by page/node id; copies can share ids. Each entry: schema version, confirmed document, server revision, loaded/unloaded page sets, page content generations, validation state, bytes estimate, last access, connection epoch, freshness, pending-outbox reference (not a second mutable queue). Local entries use mutation generation; native entries use read revision. Views/camera/selection are per-user local state, separate from server document authority.

- Local hits reuse existing library state; avoid redundant clone/stringify/check when immutable content generation proves unchanged, while preserving documentSafety checks at external inputs and recovery behavior. Do not create a second unbounded copy of the library.
- For active-room loaded pages, keep authoritative loaded data and apply every accepted server operation, including inactive-page edits. Increment touched page generations; invalidate dependent render entries. Root/global tokens invalidate all affected pages; page deletion drops cache; reordering and parent/layout changes invalidate geometry. Font/image decode, theme/preferences, viewport/DPR, asset URL changes invalidate rendered representation as applicable.
- For unloaded pages, retain today's ordered-socket fill/deferred mechanism. An evicted/old render preview can be displayed provisionally, but must **not** cause isUnloaded=false, omit the fresh page request, or make stale cached nodes the confirmed document. If evicting authoritative page data, explicitly mark unloaded and use the existing fetch flow; never evict pages with pending/deferred/history dependencies without a proven reconstruction path.
- Inactive rooms: choose **SWR**, not multiple background room sockets for the initial implementation. Display cache as a read-only presentation immediately after outgoing safety barrier; start HTTP/socket refresh concurrently. Mark stale/offline visibly outside the requested logo-only canvas if reconciliation cannot finish. Existing outgoing flush failure must still block switching; don't drop it merely to improve latency.
- Rejoin authoritative state from confirmed+pending+deferred using existing outbox client/batch ids and ack pruning. Apply fresh snapshot, then only still-unacknowledged local operations, retaining current local page/view. Do not diff a stale cache against fresh server state and turn remote differences into new local edits. Existing restore/offline-file diff needs a recorded baseline proving which edits are locally authored. Provisional cache display must not trigger library sync, localChange, undo checkpoint or native save.
- Buffer accepted remote messages during hydration in socket order. Snapshot revision establishes baseline; only subsequent ops apply. HTTP state older than socket state cannot overwrite it. Gap/reconnect/unknown epoch invalidates freshness and requests sync; `same` only trusted for the exact confirmed revision and matching loaded page set. Repeated page messages cannot overwrite already-newer loaded pages. Don't infer continuity solely from max(revision), since duplicate acknowledgements can carry current revision without new operations.
- Security/account changes namespace or purge presentation cache. Revocation/deletion invalidates authorized room cache and cancels outstanding loads; preserve existing explicitly detached local-copy behavior rather than silently reopening it as a live room. Never store access tokens in render keys or diagnostics.
- Native reopen needs trusted path-based read/reattach (current designOpen only opens a dialog), or treat native tabs explicitly as detached library copies. If adding reopen, compare cached revision with fresh disk revision, preserve unsaved local edits and existing conflict confirmation; never overwrite disk based on a stale cached revision.

### Render cache staging

First implement bounded data/SWR and remove unnecessary serialization on view-only changes; measure before complex DOM retention. Existing node reuse/culling already helps stable pages. If DOM caching is justified, move complete renderer state, not just child nodes: els/memos/owner/dirty/index/culling state, token generation, observers, shader start/stop lifetimes, camera sizing and preview ownership. Park outgoing trees, suspend shaders/previews, reconcile all nodes against current model before reveal, and release resources on eviction. Preserve one active #canvas and no duplicate selector-visible layers. Remote updates can invalidate parked renders lazily; correctness comes from full reconciliation on activation. Tiles can be keyed by file/page/content generation/zoom/DPR, but remain an optional approximate preview, never the sole faithful representation for text/shaders/interactive previews.
