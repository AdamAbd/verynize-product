# Pen image generation / Codex-login investigation

Date: 2026-11-06. Tags: **observed-live** = this Mac/UI/command output; **observed-in-source** = shipped files or generated protocol definitions; **inferred** = interpretation/proposal, not a traced request.

## Conclusion

- **observed-in-source:** Installed Pen **1.2.22** implements its normal image-generation command through **Pen's hosted service**, not a Claude-to-Codex image bridge: `POST https://api.pencil.dev/public/generate-image`, authenticated with the **Pen session**. The request contains the prompt, separately configured image provider and organization ID. References below.
- **observed-live:** With **Claude Opus 5.5** selected and **Nano Banana Lite** selected for images, a scratch-document request produced a blue-teapot raster without entering an image API key. The image picker lists **no Codex or ChatGPT image provider**. OpenAI Image models are shown with **Upgrade** on the current Free account.
- **inferred:** “Claude chat can generate images without BYOK” is confirmed for this installation. “It does so using the user's Codex/ChatGPT login” is **not confirmed**, and the inspected normal generation path contradicts that explanation. An older build or an agent invoking Codex itself could behave differently.

## (b) Pen mechanism and extracted-source references

All paths below are relative to **`extracted/app/`**. Original extracted files are unchanged. Minified renderer lines are long; `evidence/core-source-excerpts.txt` retains located excerpts with original line/character offsets.

### Image path

- **observed-in-source:** `node_modules/@ha/shared/src/image-generator-provider.ts:1–33` enumerates `nano_banana`, `nano_banana_lite`, `openai_gpt_image_2`, `openai_gpt_image_flare`, `openai_gpt_image_sunburst`; default/free provider is `nano_banana_lite`; legacy `openai` normalizes to `openai_gpt_image_2`. These are Pen provider IDs, **not proven upstream model IDs**.
- **observed-in-source:** `out/editor/assets/index.js:509`, class `$kn`, `generateImage(prompt)`: starts a pending asset; reads `manager.config.data.imageGeneratorProvider`; calls `sendAPIRequest("POST", "generate-image", {prompt, imageGeneratorProvider, organizationId})`. No Codex binary, OAuth token lookup, OpenAI Responses call, size or quality field occurs in this method.
- **observed-in-source:** `out/editor/assets/index.js:8088`, `P2t`: takes `sessionManager.session`; fails if no session credentials; constructs `${apiHostName}/public/${route}`. JWT-like Pen session tokens are sent as `Authorization: Bearer …`, with optional device-ID header and `client` in the body. Legacy session tokens are sent with email/token/client in JSON. This is app-session plumbing, not a read of `~/.codex/auth.json`.
- **observed-in-source:** `out/editor/assets/index.js:5542` defines `kl="https://api.pencil.dev"`; line **8156** passes `apiHostName:kl` to the editor. Together with the previous two references this resolves the exact endpoint to **`https://api.pencil.dev/public/generate-image`**. This is a static call-chain finding, not a network capture.
- **observed-in-source:** `node_modules/@ha/api/src/gcp-media-provider.ts:7–36` specifies response `{success,image?,error?,content_violation?,request_id?,version?,credits_used?,credits_remaining?}` and body `{prompt,imageGeneratorProvider?}`. Renderer additionally supplies organization ID. Client schema exposes no size/quality control here. Actual upstream model, dimensions and quality policy live server-side and are unproven.
- **observed-in-source:** Renderer line **509** receives base64 `image`, decodes it using `l3` (base64 decoder at line **10**), replaces preview bytes, calls IPC `import-files` with `{kind:"image",fileName:"generated.png",fileContents:<bytes>}`, and returns the resulting `fileURI`. It does not consume a Codex saved-path event.
- **observed-in-source:** Renderer line **509** reports failed/no-image responses with a generation-failure toast; recognized usage-limit errors emit `imageGenerationLimitReached`. Class `Ukn` waits for a Pen session. Line **1057**, `handleGenerateImage`, rejects absent Pen authentication and checks image-generation allowance before invoking the image manager. Lines **1028 onward** instruct agents, in paraphrase, to retain empty nodes after quota exhaustion and tell the user to upgrade instead of repeatedly generating or replacing the requested artwork.
- **inferred:** No-Codex-login error is inapplicable to this normal image path: its checks are Pen login and plan allowance. Actual logged-out behavior was not tested; no accounts were signed out.

### How Claude gets image access

- **observed-in-source:** `node_modules/@ha/agent/src/claude/index.ts:115–150`: derives allowed names from MCP schemas, prefixes them `mcp__pencil__`, and registers the `pencil` MCP server in Claude SDK options.
- **observed-in-source:** `node_modules/@ha/mcp/dist/schemas-FZHc2sXP.mjs:68–122`: tool **`execute`** (Claude name **`mcp__pencil__execute`**) accepts `uri` (required), `description`, JavaScript `input`, or repair fields `editId` and `edits[{find,replace,all?}]`. It is the design interpreter, not a dedicated `generate_image` tool in this build.
- **observed-in-source:** Renderer line **1057** handles **`Generate("ai", nodeId, prompt)`**, validates type/node/prompt, checks Pen login/usage, calls `generateAIImage`, and installs a covering image fill on the node. Other modes include stock and SVG. Thus Claude can request an image through the same design tool without being an OpenAI agent.
- **observed-in-source:** MCP schema line **199 onward**, `read_skill`, exposes the Pen design skill and its referenced execution documentation. Paraphrased guidance: read the app/skill documentation, execute design operations, create the target node, then use the Generate operation to fill it; do not fake completion when quota prevents generation. No long system prompt is reproduced here.

### Codex path is separate (chat agent)

- **observed-in-source:** `out/codex.js:9–15` chooses the bundled `app.asar.unpacked/node_modules/@openai` package root. `node_modules/@ha/agent/src/codex/index.ts:537–559` resolves the platform-specific binary. On Apple Silicon its constructed path is `/Applications/Pen.app/Contents/Resources/app.asar.unpacked/node_modules/@openai/codex-darwin-arm64/vendor/aarch64-apple-darwin/bin/codex`.
- **observed-in-source:** Same file **65–128** uses `@openai/codex-sdk` with the selected agent model, optional agent API key, `features.plugins=false`, and a `pencil` MCP server. Thread settings: workspace-write, skip Git-repo check, working directory, web search, effort, approval policy never. `execute` is a chat-agent session, not an image service.
- **observed-in-source:** `node_modules/@openai/codex-sdk/dist/index.js:178–267` spawns **`codex exec --experimental-json`**, plus `--config` overrides, `--model`, `--sandbox workspace-write`, `--cd`, `--skip-git-repo-check`, optional reasoning effort, web-search setting, approval policy and optional `resume <threadId>`. Optional API key becomes `CODEX_API_KEY`. The package manifest pins SDK **0.165.0**. This is not `codex app-server`.
- **observed-in-source:** Bounded searches of Pen `@ha` sources/distributions and desktop JS did not find a normal image bridge using `image_generation_call`, `chatgpt.com/backend-api`, `auth.json`, `CODEX_HOME`, or app-server image RPC. The exact positive image call chain above is stronger evidence than a negative string search. Dependencies and external model-driven shell actions may support additional behavior.

## (c) Local Codex CLI capabilities

- **observed-live:** `/opt/homebrew/bin/codex --version` → **codex-cli 0.166.0**. Captured help, app-server help and feature output in `evidence/codex-*.txt`. This is distinct from Pen's SDK version.
- **observed-live:** `codex features list` reports **`image_generation stable true`**. CLI `--image` is input attachment, not by itself an image-generation command. `exec`, `app-server`, login and feature commands are available.
- **observed-live:** Ran `codex app-server generate-json-schema --out <output>/evidence/codex-schema` successfully. Only the two standalone schemas cited below (`ClientRequest.json` and `ServerNotification.json`) are retained; unused generated schemas were removed during repository cleanup. Both retained files are self-contained, with internal references only. App-server help exposes stdio, Unix and WebSocket transports, schema/TS generation and daemon/proxy commands.
- **observed-in-source:** Generated `evidence/codex-schema/ClientRequest.json:6344` and **7833** expose `thread/start` and `turn/start`; `ServerNotification.json:7835` exposes `item/completed`. No dedicated `image/generate` request method was found in ClientRequest.
- **observed-in-source:** Generated `ServerNotification.json:5390–5500` has **`ImageGenerationThreadItem`**, type `imageGeneration`, `id`, `status`, optional `revisedPrompt`, `savedPath`, `transparentBackground`, `failure`, `inputImages`, `generationId`, and either inline `result` or durable `fileId`. Do not assume every result is inline base64: this installed schema explicitly supports stored attachments. `ClientRequest.json:3717` also contains `image_generation_call` as a response-item variant, not a standalone RPC method.
- **observed-in-source:** Context7 resolved `/openai/codex` and returned current upstream image-extension source/test documentation: successful generation saves output and emits a completed image item with a saved path. The returned upstream snippets differ from this machine's schema in some fields, so the generated **0.166.0 schema takes precedence**. Source links: https://github.com/openai/codex/blob/main/codex-rs/ext/image-generation/src/tool.rs and https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/suite/v2/imagegen_extension.rs .
- **inferred:** A **new Verynize implementation** could run a separate Codex session through app-server, request its built-in image tool, consume image completion/savedPath or attachment data, and expose the result to Claude through Verynize's own generate_image MCP tool. This is technically suggested by local protocol support; it is **not the observed Pen implementation**, and ChatGPT entitlement/model availability still need an end-to-end Codex-only test. No local auth tokens were opened, no login status containing identity was captured, and no Codex image request was executed here.

- **inferred (unproven):** Pen's upstream image API implementation, actual provider credentials, exact upstream models, server size/quality controls and billing remain unavailable in the client bundle. UI labels are not evidence of OpenAI model identifiers.
- **inferred (unproven):** No traffic capture was performed. Endpoint/auth provenance are source-backed; image production and selected UI settings are live-backed. The runtime response bytes were not intercepted.
- **inferred (unproven):** No controlled logout test, OpenAI premium-image generation, alternate-provider purchase, or Codex-only generation was performed. Existing accounts/preferences were not reset to create a “no key” environment.
- **inferred (unproven):** Dedicated canvas context-menu generation and full Codex authentication UI were not exhaustively exercised. Toolbar, chat image picker, General image setting and Agents entry screen were inspected.
